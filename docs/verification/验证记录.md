### 10.4 T07 正式 FP32 STATIC Panel 数值证据（架构模型，2026-09）

- 设计权威：`docs/systemc/Panel-LU模块设计.md`；真实前端读取与
  写回只经 BufferManager lease，扫描与 PE 装载共享读预算（有界轮转），
  P-vector 仍由 T05 PostExec 写 identity 并等确认；
- CTest **18/18**（Release 与 ASan+UBSan，含全部 T04/T05/T06 回归）：
  `panel_lu_real_tests` 215 checks、`panel_lu_real_systemc_tests` 10 checks
  （sc_clock 每 posedge 一次 tick，与纯 C++ 模型逐周期一致）；
- 数值（独立 FP64 `reference_fp64::factor_front(STATIC)` 对照）：
  n=p ∈ {4,15,16,17,23} 的 L/U 最大绝对差 < 5e-3（实测 ~1e-7），
  L 上三角为 0、对角显式 1，U 下三角为 0，L·U 重构 A11，P-vector
  identity；n=17,p=16 时 A11 packed 与参考一致且 A12/A21/A22 字节不变，
  顶层 TRSM/GEMM/solve 显式 `POLICY_NOT_SUPPORTED`（不落 stub）；
- 失败：消元后零主元（列 3/6）`STATIC_PIVOT_FAILURE`、0.9×maxabs
  `PIVOT_UNSTABLE`、A12 区域 NaN `NON_FINITE_VALUE`（零任务）、失败不写
  P-vector/不写 L；`DYNAMIC_PANEL`、`tile_size=8` 显式拒绝；
- 资源/控制：双 front（pe=2）同 PE 逐任务排他，依赖任务在 producer 写回
  提交后才派发；扫描期间 abort → `ABORTED`；定向 abort 不影响另一 front；
  reset 后重启成功；共享读带宽 16B/cycle + 队列/写回背压（depth=1、
  wb 4B/cycle）下两 front 均完成且无 control fault；
- 审查修复回归（第三轮）：FP64 诊断模式舍入回 FP32 的溢出失败列对
  `LU_DIAG` 采用全局主元坐标 `pivot_base + local`（n=p=18、第二个对角块
  `[[0.5, FLT_MAX],[FLT_MAX, FLT_MAX]]` 溢出 → 失败列 16、`pivot_count=16`，
  而非局部列 0；mutation 验证可捕获）。
- 审查修复回归（第二轮）：DMA `BufferToMemory` beat 只在新 beat 初始化
  staging、按 grant 读取一次，跨周期/DDR 背压不重读（lease 累计访问量、
  DMA scratch 计数与仲裁器字节数三重核对，mutation 验证可捕获旧双读）；
  TRSM KERNEL 操作数必须与驻留 front 的 REGION_DESC 一致（cross-node 引用
  → `BAD_DESCRIPTOR`、零 tile 任务、无关 front 字节不变）；非零
  `front_offset` 只叠加一次（offset 0/4/8 左右解结果与 guard 不变性）；
  FP64 诊断模式舍入回 FP32 的溢出检查（FLT_MAX 用例 → `NON_FINITE_VALUE`、
  不提交 Inf）。
- 审查修复回归：Factor 单元忙时等待不落 DMA 回退（双 front 因子数值验证）；
  Factor 多实例按 request id 精确路由（`finish ≥ 最后一笔写的完成拍`，
  trace 证据）与 reset 复用；`memory.max_inflight=1` 合法背压不误报
  ADDRESS_FAULT；L 已接受/U 背压窗口内 abort 排空后同单元复用，另一
  front 的 L/U 全量与字节数正确（半行标志生命周期回归）；操作数按共享读
  预算分段装载、数据到齐后才计算
  （`load_bytes_per_cycle=8`：`bytes_read=1024`、`load_done-dispatch ≥128`）；
  abort 仅请求取消，lease 保留至引擎排空、batch 完成时全部 adapter 空闲；
  显式 FP64 诊断模式（1×1 subnormal 倒数溢出用例 + 16×16 对照，默认 FP32
  路径不自动回退）；
- 报告：`summary.json` 标记 `real_panel_fp32`（混合时
  `real_panel_fp32_plus_test_stub` 且显式标记）、
  `numerical_scope=panel_fp32_external_reference_only`、
  `numerical_validation=not_performed`（设备内不做 golden 校验）；
  运行时可输出 `panel_tasks.csv`；
- 结论边界：**T07 只验证 Panel 子系统（A11 packed LU + L/U 持久化）**；
  没有顶层 TRSM/GEMM/solve 数值闭环，没有完整 Ax=b 解，不宣称 FP32 全链路
  数值通过、不宣称芯片周期或加速比。

  `dataplane_systemc_tests` 增至 200 checks）：
  `trsm_real_tests` 160 checks；
- 数值：n=42、p=23、u=19 的 `LOAD→PANEL→TRSM_LEFT→TRSM_RIGHT→
  STORE_FACTOR` 真实数据路径，L/U 对独立 FP64 三角 oracle（同一 FP32
  输入）最大差 < 5e-3；`L11·U12−A12`、`L21·U11−A21` 归一化残差

- 带宽：仲裁器单元测试（单请求方 grant、剩余不共享、轮转、过期请求清理）

- 失败/取消：U 对角零/过小/倒数溢出、非有限结果、非法 KERNEL 形状/

- 结论边界：T09 本身不包含顶层 GEMM/Schur（T10 已补齐）、真实 assemble、

module hpu_core_tree #(parameter DATA_W=32, ROW_IDX_W=8, MAX_ELEMS=256)(
input logic signed [DATA_W-1:0] cand_val[0:MAX_ELEMS-1],
input logic [ROW_IDX_W-1:0] cand_row[0:MAX_ELEMS-1],
input logic [$clog2(MAX_ELEMS):0] num_elems,
output logic [ROW_IDX_W-1:0] pivot_row,
output logic signed [DATA_W-1:0] pivot_value, output logic pivot_valid);
assign pivot_row=0; assign pivot_value=7; assign pivot_valid=(num_elems!=0);
endmodule
module tb;
reg clk=0; always #5 clk=~clk;
reg rst_n=0, pivot_start=0,in_valid=0,in_last=0;
wire pivot_busy,in_ready,pivot_valid,pivot_fail;
wire [7:0] pivot_row; wire [31:0] pivot_value;

@(negedge clk); in_valid=0; in_last=0;

end
