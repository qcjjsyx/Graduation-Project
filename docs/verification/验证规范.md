# 验证规范

更新：2026-10-11。本文规定验证对象、判据、指标和证据保存方式。
具体回归、缺陷复现与文档核查见 [验证记录](验证记录.md)；阶段完成情况见
[当前进度](../../当前进度.md)，未完成工作见 [todo](../../todo.md)。
实验设计、批次数据和图表保存在 [精度边界实验](../../experiments/precision_boundary/实验报告.md)
与 [真实矩阵诊断实验](../../experiments/real_matrix_diagnosis/实验报告.md)。
接口字段与失败码以 [Command Schema v2](../interface/Command_Schema_v2.md) 为准，
数学定义见 [数值误差分析理论基础](../theory/数值误差分析理论基础.md)。

## 1. 验证原则

- 设备按 schema v2 接收数据、Command、Descriptor 和 Completion；FP64 参考只用于独立验收。
  设备不得读取 golden 文件，参考因子、主元或解不得回填设备输入或执行状态。
- 手算结果、共享固定 fixture 或独立参考产生期望值；不得用被测函数生成自己的期望值。
- 主元策略来自 descriptor，必须显式声明；因子比较只在同一策略内进行。
  静态固定顺序失败不构成矩阵奇异性的结论。
- 分开报告控制完成、数值命令状态、因子验收、三角求解验收与原方程解的精度。
  `status=OK` 表示对应命令执行成功，不能据此认定 `Ax=b` 求解准确。
- 原方程误差使用原始 `A`、`b` 及恢复坐标后的 `x`；设备变换系统和三角系统的误差另行标明。
  缺少原方程数据或参考解时标为不可用，不能以默认零值当作测量结果。
- 数值失败、NaN/Inf、超时和依赖失败必须保留，不得静默替换小主元或删掉失败用例。
- 测试预期失败必须与实际状态码、失败列及依赖传播一致；预期失败不计为数值成功。

## 2. 分层验证

| 层次 | 验证对象 | 核心要求 |
|---|---|---|
| L0 独立数学参考 | Python FP64 front-tree 与独立 C++ FP64 reference | 同策略 LU、TRSM、Schur、树形求解、置换、失败分类及误差计算；两套参考共享固定用例交叉验证 |
| L1 软件产物 | 输入、预处理、符号结构、命令和镜像 | 数值不被对称化；元素唯一归属；变换后重算结构；记录、映射、地址、依赖和容量合法 |
| L2 设备模块 | 取指、调度、存储、装配、数值单元和求解单元 | 数据正确性、资源排他、时序、反压、失败传播、取消与复位分别验证 |
| L3 节点与整树 | 节点分解、森林、前代与回代 | 真实 child update 装配、因子/update 可见性、依赖、释放/复用、解写回与独立验收 |
| L4 RTL 对照 | 已存在且接口可对应的 RTL 模块 | command/descriptor、握手、复位、反压、状态、数据、主元/P-vector 和错误事务对照 |

### 2.1 参考与软件产物

Python 参考入口为 [`front_reference.py`](../../graduation-code/software/src/verify/front_reference.py)，
C++ 参考入口见 [模型规范 §8](../systemc/SystemC模型规范.md#8-独立-fp64-参考与验收代码入口)。
编译期 `reference_check` 默认关闭；开启时可做数值预检，不能把参考求解成功设为正常编译的必要前提。
外部 RHS 的参考解也仅在显式参考检查时生成；没有生成参考解不等于设备失败。

共享用例 [tree_policy_cases.json](../../graduation-code/fixtures/reference_tree/tree_policy_cases.json)
由 Python `test_reference_cross.py` 和 C++ `fp64_reference_tests` 分别执行。
通用稠密部分主元 API 与设备契约 `panel_lu_policy()` 分开使用；`generic` 参考只能作独立求解对照。

软件产物必须检查：

- `B=P_match D_r A` 的数值保持，符号包络采用 `pattern(B) ∪ pattern(Bᵀ)`；ordering、fill、etree、
  supernode、front、map 在变换后整体重算，结构和 forest 一致。
- 原始元素唯一归属；descriptor/map、镜像 region、对齐、容量和地址范围合法，无重叠或整数溢出。
- manifest `abi.version=2`，Command/Descriptor/Completion 大小为 32/64/64 字节；记录长度、引用和 token 合法。
- `FRONT_DESC.word8/9` 与 manifest 的策略/阈值一致；P-vector 为 INT32、长度 `pivot_dim`、初值 `-1`，
  引用有效；置换组合符合 gather 语义 `y[i]=x[p[i]]`。

### 2.2 设备模块与整树

各模块按对应设计验收，入口见 [总体架构](../architecture/项目总体架构设计.md#3-设备子系统与连接关系)：

- 取指/控制面：固定记录读取、有界窗口、token 的 PENDING/READY/FAILED、依赖失败传播、双 front 驻留、
  共享执行单元、运行时故障与 loader 故障的区分。
- 数据面：加载、region/bounds、descriptor 读取、buffer 生命周期、DMA 1D/2D、尾块、延迟、背压与 reset。
- 装配/因子保存：child DDR update 经 DMA 和 scratch 进入父节点，按运行时 map 做 FP32 extend-add；
  因子/update 写回完成后才能提交可见性或释放空间。
- Panel/TRSM/GEMM：完整因子和 Schur 对独立参考；tail、K 分块屏障、扫描尺度、实际主元、
  同目标 tile 更新顺序、同一 PE 跨模式排他和跨 front 公平性。
- 局部 INT32：实际实现为 Precision Adapter 函数及 `MultiModePe` 调用，验证量化、反量化、饱和和溢出；
  不能将设计职责名称 `Int32GemmBehavioral` 当作现有同名 C++ 类。
- 求解：前代/回代依赖、局部 P-vector、变量映射、更新 RHS、解写回、DMA 反压及 abort/reset。
- 原型/stub：输出必须标记 `numerical_validation=not_performed`；合成负载的资源/时序测试不代替数值验收。

节点路径覆盖 `LOAD → ASSEMBLE → PANEL → TRSM → SCHUR → STORE → COMMIT`；
整树覆盖多层 child、任意任务顺序、父节点等待全部 child、多根 forest、迟到 child、buffer 释放/重新分配、
写回后重新读取和分解后的树形求解。先验证 STATIC 闭环，动态主元接入后必须对两条路径分别回归。

### 2.3 RTL 与行为模型对照

RTL 对照必须比较同一事务契约的接受/拒绝、valid/ready、复位、反压、状态转移、数据和错误。
尚无对应 RTL 时，只能记录未来接口所需的行为模型测试，不能称为 RTL 数值验证。
独立 HPU/ATU 原型通过不代表动态主元整树或 GCU 集成通过。

## 3. 主元策略验收

策略是 batch 级统一策略，来自 schema v2 `FRONT_DESC`，不支持逐命令混用。

| 策略 | 主元行为 | 必须验证的失败语义 |
|---|---|---|
| `STATIC` | 固定顺序，无搜索/换行；动态映射运行时旁路；写显式 identity P-vector | 零主元 `STATIC_PIVOT_FAILURE`，非零但过阈值 `PIVOT_UNSTABLE`，非有限值 `NON_FINITE_VALUE` |
| `DYNAMIC_PANEL` | 仅 pivot block 的行 `k..pivot_dim-1` 内最大绝对值；并列取最小逻辑行号 | 接入后验证 `PIVOT_NOT_FOUND`、`PIVOT_UNSTABLE`、`NON_FINITE_VALUE`；当前设备应拒绝为 `POLICY_NOT_SUPPORTED` |

STATIC 检查消元后的实际主元，尺度固定为 front 装配后、消元开始前一次归约的
`front_pre_elimination_max_abs`。非零主元满足
`abs(pivot) <= threshold_ratio * front_pre_elimination_max_abs` 时失败。
失败不发布 READY、不替换主元、不在运行中切换策略；host 重试应重建完整状态。
动态事务的运行时旁路与综合裁剪属于不同验证对象。

DYNAMIC_PANEL 接入必须覆盖范围、tie-break、局部置换及对前代/回代的影响。
跨 front 换行、update 行提升为 pivot、delayed pivot 和动态 front 扩张不在该策略契约内。
不能从 P-vector 是否 identity 猜测策略，也不能用动态参考结果代替尚未执行的设备动态验收。

## 4. 数值指标与通过条件

### 4.1 三角求解与原方程分别报告

设原方程残差为 $r=Ax-b$。当前工具的字段命名沿用实现，必须同时注明实际定义。

| 指标 | 当前定义与含义 | 来源 |
|---|---|---|
| `eta_forward`、`eta_backward` | 分别为设备因子的前代/回代分量后向误差；分母为相应三角算子绝对值与解绝对值的乘积，加 RHS 绝对值 | `tree_solve_check` |
| `original_relative_residual` | $\lVert r\rVert_\infty/(\lVert A\rVert_\infty\lVert x\rVert_\infty+\lVert b\rVert_\infty)$；这是归一化残差，不是 $\lVert r\rVert/\lVert b\rVert$ | `tree_solve_check` |
| `original_backward_error` | $\max_i \lvert r_i\rvert/(\lvert A\rvert\lvert x\rvert+\lvert b\rvert)_i$，原方程分量后向误差 | `tree_solve_check` |
| `original_solution_relative_error` | $\lVert x-x_{true}\rVert_2/\lVert x_{true}\rVert_2$，有已知真解时报告；否则另报独立 FP64 参考对照误差 | `tree_solve_check` |
| `transformed_*` | 同样口径用于设备变换系统 $\widehat A\widehat x=\widehat b$，不能代替原方程指标 | `tree_solve_check` |
| host `relative_residual` | $\lVert r\rVert_2/(\lVert A\rVert_F\lVert x\rVert_2+\lVert b\rVert_2)$，与 checker 的无穷范数口径不同 | FP64 reference、`numeric_diagnosis.py` |
| 条件数、节点/全局分解后向误差、增长、最小主元比 | 分别描述问题敏感性、分解质量和主元风险；范数/增长定义按对应实验报告注明 | host 数值分析 |

源码权威见 [solve checker](../../graduation-code/systemc/reference/src/tree_solve_check.cpp)、
[FP64 指标](../../graduation-code/systemc/reference/src/fp64_reference.cpp) 和
[诊断工具](../../graduation-code/software/tools/numeric_diagnosis.py)。不同工具同名字段可能使用不同范数，
跨表比较应先核对定义；解误差的参考来源和 golden 可用性也必须标明。

### 4.2 现有 checker 的判定边界

- `tree_factor_check` 验证完整 L/U/update/P，默认容限 `1e-4`，写 `validation.json.numeric_pass`。
  病态或增长较大的矩阵逐元素因子对照失败时，仍应保留原始判定，并补充后向误差、条件数和解误差。
- `tree_solve_check` 的 `solve_pass` 要求求解命令全部 OK、`eta_forward` 和 `eta_backward` 均不超过
  默认容限 `1e-4`；原方程/变换系统误差和解误差已报告，当前未作为该 flag 的通过门限。
- “原方程解可用”的门限由实验事先声明，不能用 `solve_pass` 替代。
  精度边界实验的单次解误差 `1e-3` 和迭代求精双指标判据见其 [报告 §4](../../experiments/precision_boundary/实验报告.md#4-判据2026-10-11-用户确认)。
- 原方程后向误差小仍可能伴随大解误差；不能把严重病态输入的执行成功写为最终解准确。

### 4.3 FP32 与局部 INT32

FP32 结果允许跨平台浮点末位差异，按误差量级和容限验收，不要求逐位相同。
报告输入/消元产生的 NaN/Inf、overflow/underflow、主元失败、失败节点和列，以及实际周期与流量。

局部 INT32 GEMM 行为路径已实现，FP32 仍承担装配、Panel、TRSM 和求解；本项目不做全局量化或 BFP。
验收包括输入量化、tile GEMM、Schur 误差、scale/round/saturation/overflow、转换开销、失败状态，
以及 Schur 误差传到父 front 后对静态实际主元的影响。不做整树 bit-exact 比较，
不得用 FP64 pivot 覆盖量化改变后的真实主元。可手算良态 INT32 局部用例用独立 INT64 oracle 精确对照。

## 5. 测试输入与负面用例

覆盖以下输入并为两种策略分别保存因子/P-vector 和验收结果：

- 可手算小矩阵、STATIC 直接成功、需 host 行匹配后才能 STATIC 成功、近零主元、NaN/Inf、tie-break。
- 陷阱矩阵 `[[1,1,0],[1,1,1],[0,1,1]]`：初始对角非零但 STATIC 消元产生零主元；
  动态参考及接入后的设备在可用 panel 范围内验证成功；跨 pivot block 的候选行必须拒绝。
- 结构对称但数值非对称、非恒等匹配与非恒等排序、稳定随机稀疏矩阵、多层树及多根森林。
- 小主元、高增长、front 接近容量边界、高节点数/高依赖扇入，以及仓库的 256/576/1024 规模矩阵。
- 非法 map、损坏 descriptor、地址重叠、截断记录、非法策略/版本和混合 v1/v2 descriptor。
- P-vector 的非法引用、哨兵未改写、越界、重复值、全零冒充 identity；区分 loader 初值检查与执行后置换检查。

预处理验证二的幂行均衡与一对一 max-product 加权行匹配，不能用逐列贪心或 MC64 的名称代称实现。
`P_match` 与 `Q` 必须是双射，匹配只用有效非零，无完整匹配时诊断失败、不产出 artifact。
逐项验证 $B=P_{match}D_rA$、$\widehat A=Q^TBQ$、$\widehat b=Q^TP_{match}D_rb$、$x=Q\widehat x$，
以及 gather/scatter 方向。参考测试见 `test_transform_semantics.py` 和 `test_matching.py`。

## 6. 控制、资源与时序

必须覆盖重复完成 token、token 下溢、child 顺序变化、取指截断、错误版本、策略拒绝、依赖失败传播、
buffer 满/空、DMA 延迟/带宽变化、共享端口竞争、completion 背压、HPU 反压、ATU 初始化/swap/reset、
GEMM K 分块、量化饱和/溢出、timeout、abort 与旧 epoch 响应无效。
有限 task slot/队列、存储背压、公平性与同 tile 更新顺序也需要定向用例。

纯 C++ tick 与 SystemC `sc_clock` 对照必须使用一致的推进规则；原型时延需由数据流和流水参数推导。
凡性能计数只作统计、尚未影响真实完成周期的部分，应单独说明，不能视为完整时序模型。

## 7. 性能测量口径

在同一数值判据和配置下报告总周期/各阶段周期、DDR bytes、buffer 占用、计算资源忙碌率、
dependency stall、转换开销、串行/资源感知调度差异，以及 tile/lane/带宽/延迟扫描。
分开记录 SystemC 模型周期与 host 墙钟时间，并注明实际影响完成时间的模型参数。
SystemC 周期不是芯片实测频率或吞吐；局部模块测试与算法操作数不支持硬件加速比结论。

## 8. 证据文件与归档

### 8.1 设备运行与独立验收

当前 `tree_factor_device` 的报告包括：

```text
summary.json
commands.csv
nodes.csv
units.csv
fronts.csv
panel_tasks.csv
transactions.csv
buffers.csv
final_memory_image.bin
```

独立 checker 分别补充 `validation.json` 与 `solve_validation.json`。
solution 保存在最终镜像的 `solution_data` region；不将未实现的 `solution.csv` 等列为现有必备输出。
输入 `manifest.json` 和初始镜像也应与报告对应保存；原方程 FP64 文件供 checker/host 分析使用，不供设备读取。

设备 summary 的 `control_flow_pass`、`numeric_status_pass` 与 checker flag 分开解释。
设备保持 `numerical_validation=not_performed`，表示它没有替自己完成独立数值验收。
batch 元数据补充矩阵来源、seed、配置、schema、策略/阈值、工具参数、代码/二进制版本、环境和文件 hash；
这些信息不能假设已全部存在于设备 `summary.json` 中。

### 8.2 验证记录与数值实验

回归记录保存日期、实际命令、环境、配置、通过/失败数量、缺陷复现与修复结果，并链接原始证据。
完成概述写根目录 [当前进度](../../当前进度.md)；未完成事项写 [todo](../../todo.md)，避免在规则中重复维护状态。

数值实验按 `experiments/<experiment>/实验报告.md` 与 `results/<batch>/` 管理。
每批保存 `metadata.json`、原始逐例 JSON、汇总 CSV、图表；报告说明数据范围、方法、判据和限制。
已归档批次不原地覆盖，新跑和补跑建独立批次；改变方法或统计范围时，更新报告并保留旧数据来源。
脚本留在软件工具目录，报告链接实际入口。

旧数据缺少环境、原始结果或确切代码版本时标记未知，不能用迁移当天的状态填充成原始执行信息。
大矩阵、设备镜像与长 trace 按实际复核需要保存；至少保留生成规格、seed、原输入 hash 和可追溯来源，
并说明未保留项目及复现限制。临时目录只能作运行 workspace，不能作为唯一证据存放位置。

## 9. 结果来源标记

结果表必须标明实际来源：`HOST_FP64_REFERENCE`、`SYSTEMC_FP32_DEVICE_MODEL`、
`SYSTEMC_INT32_GEMM_MODEL` 或 `RTL_CONTROL_PROTOTYPE`。
只有存在且实际运行对应 RTL 时才使用 RTL 计算结果标签。
行为模型、周期估计和 RTL 结果分别标记；DYNAMIC_PANEL 的设计契约/参考行为不能写成设备已实现。
