# 验证计划与结果口径

状态：当前主线文档

## 1. 验证原则

验证必须区分数学正确性、硬件控制正确性、数值格式误差和性能模型。`status=OK` 只表示控制流完成，不表示解的精度达标。

主元策略切换后补充以下原则：

- 主元策略（`STATIC` 默认 / `DYNAMIC_PANEL` 可选）必须显式声明，绝不从 P-vector 内容猜测；
- `STATIC` 固定顺序失败（`STATIC_PIVOT_FAILURE`）**不是**奇异性结论，不得写成“矩阵奇异”；
- 因子（L/U/P）对照只在同一主元策略内进行；`STATIC` 与 `DYNAMIC_PANEL` 可能产生不同因子，互不覆盖；
- residual 和 backward error 一律对原始 `A x = b` 计算；host 数值预处理变换只存在于编译侧，不改变误差口径；
- 相对解误差以独立高精度求解为基准（独立 C++ FP64 参考），不允许设备输出自证。

## 2. 五级验证层次

### L0：数学黄金参考

使用 FP64 参考验证，参考分两套且互相独立：

- host Python FP64 front-tree 参考（`graduation-code/software/src/verify/front_reference.py`）：独立验证入口；仅在显式开启 `reference_check` 时做编译期预检与 checker（默认关闭，正常编译不以数值求解成功为前提，允许生成用于验证设备主元失败的输入；外部 RHS 的 golden 参考解同样只在此时求解，未开启时参考解文件与指标缺省），不进入设备路径；
- 同策略整树交叉验证：共享 fixture `graduation-code/fixtures/reference_tree/tree_policy_cases.json` 固定装配、主元策略、局部 P-vector、求解与失败分类的期望值，Python（`tests/test_reference_cross.py`）与 C++（`fp64_reference_tests`）必须同时复现；`fp64_reference_smoke` 的 `generic` 模式仅作独立求解对照，`static`/`dynamic_panel` 模式走设备契约策略；
- 独立 C++ FP64 参考（`graduation-code/systemc/reference/`）：提供 `PivotPolicy{Static, DynamicPanel}`、`PivotFailure`、`panel_lu_policy()`（设备契约）和经典 `panel_lu()`（通用稠密部分主元 API，数学能力完整，但**不是**设备契约）；两者必须清晰分离，front-tree solve 强制置换范围不超过 pivot block。

必须覆盖：

- dense panel LU 与两种策略的主元语义：
  - `STATIC`：固定顺序、无搜索、无交换，检查消元后的实际主元；
  - `DYNAMIC_PANEL`：仅 pivot block 行 `k..pivot_dim-1` 内最大绝对值，并列取最小逻辑行号；
- P-vector 语义：INT32、长度 `pivot_dim`、gather 方向 `y[i] = x[p[i]]`、哨兵 `-1`、`STATIC` 写显式 identity、设备局部（与 host `P_match`/`Q` 映射区分）；
- TRSM；
- GEMM/Schur；
- 树形前代和回代；
- residual 和 backward error（对原方程）。

### L1：软件产物

验证：

- 原始矩阵数值没有被对称化；
- 符号模式为 `pattern(B) ∪ pattern(Bᵀ)`（`B = P_match D_r A`，在变换后的模式上重算包络）；
- ordering、fill、etree、supernode、front 和 map 在预处理变换后整体重算且互相一致；
- fill、forest、supernode 和 front 一致；
- 每个原始元素唯一归属；
- map、descriptor、地址和区域不重叠；
- 命令版本、长度和 token 正确；
- schema v2 契约一致：manifest `abi.version=2`、`FRONT_DESC.word8/9`（策略/阈值）与 manifest pivot 块一致、P-vector 引用非 `NONE`、P-vector region 为哨兵初值、置换数组互为一致组合。

### 多模式 PE 架构原型验收（T06，设计+原型已交付，数值未验证）

### L3：节点和整树

节点闭环：

```text
LOAD → ASSEMBLE → PANEL → TRSM → SCHUR → STORE → COMMIT
```

整树闭环覆盖：

- 多层 child update；
- 多根 forest；
- 任意任务顺序；
- 父节点等待所有子节点；
- buffer 释放和重新分配；
- factor/update 写回后再读取；
- 前代、回代和 solution 写回。

### L4：RTL/行为接口

如果某个 RTL 模块存在，必须与同接口的 SystemC 模型对照：

- command 接受/拒绝；
- descriptor 解析；
- valid/ready；
- reset；
- backpressure；
- 状态转移；
- pivot、P-vector 或 tile 输出；
- error/status。

没有 RTL 时，L4 对 `Int32GemmBehavioral` 只验证未来 RTL 所需的 transaction contract，不能称为 RTL 验证。

## 3. 主元策略验证矩阵

主元策略是 batch 级统一策略，显式声明于 `FRONT_DESC`（schema v2），不支持逐命令混用。

| 策略 | 定位 | 搜索/交换 | HPU/ATU 动态映射 | 主要失败码 |
| --- | --- | --- | --- | --- |
| `STATIC` | 默认（软件数值预处理 + 硬件固定主元顺序） | 无搜索、无交换 | 运行时旁路 | `STATIC_PIVOT_FAILURE`、`PIVOT_UNSTABLE`、`NON_FINITE_VALUE` |
| `DYNAMIC_PANEL` | 显式可选能力 | 仅 pivot block 行 `k..pivot_dim-1`，最大绝对值，并列取最小逻辑行号 | 要求启用 | `PIVOT_NOT_FOUND`、`PIVOT_UNSTABLE`、`NON_FINITE_VALUE` |

### 3.1 STATIC 必须执行的检查

- 按最终排序后的对角固定顺序消元，不搜索候选行、不交换行；
- 检查**消元后**的实际主元，而不是只检查输入对角：
  - 零主元 → `STATIC_PIVOT_FAILURE`（非奇异性结论）；
  - `|pivot| <= threshold_ratio * front_pre_elimination_max_abs`（非零）→ `PIVOT_UNSTABLE`；
  - NaN/Inf（输入或消元产生）→ `NON_FINITE_VALUE`；
- 阈值尺度固定为 `front_pre_elimination_max_abs`：front 装配完成、消元开始前的 `max|A_front|`，每 front 一次归约，不做逐列候选搜索；
- HPU/ATU 动态映射在该路径**运行时旁路**（运行时旁路 ≠ 综合时裁剪，两者分别验证）；
- 失败语义：不发布 `READY` token；不静默替换微小主元；不在运行途中切换策略；host 重试必须从原始输入或完整重建状态开始。

### 3.2 DYNAMIC_PANEL 边界

- 搜索严格限制在 pivot block 内；跨 front 换行、update 行提升为 pivot、delayed pivot、动态 front 扩张一律不支持（`PIVOT_NOT_FOUND`）；
- 未实现该能力的 executor 必须以 `POLICY_NOT_SUPPORTED` 拒绝执行，不发布 `READY` token；
- 策略只来自 descriptor 字段，任何“根据 P-vector 是否为 identity 猜策略”的路径都必须被拒绝；
- 静态与动态可能产生不同 L/U/P，因子对照只在同一策略内进行。

## 4. 数值结果口径

### 4.1 FP64 golden

主要指标：

```text
relative_residual = ||Ax-b|| / (||A|| ||x|| + ||b||)
componentwise_backward_error
relative_solution_error
pivot_growth
minimum_pivot_ratio
```

口径要求：residual 和 backward error 一律对**原始** `A x = b` 计算；`relative_solution_error` 以独立高精度求解为基准（独立 C++ FP64 参考）。

### 4.2 FP32 SystemC

允许与 FP64 存在浮点误差，但必须报告：

- 最终 residual；
- backward error；
- pivot 差异；
- overflow/underflow；
- 失败节点；
- 周期、bytes 和 stall。

### 4.3 INT32 GEMM 混合路径

不做整树 bit-exact 比较，报告：

- 输入 tile 量化误差；
- GEMM tile 误差；
- Schur update 误差；
- scale、round、saturation 和 overflow；
- 最终 residual 和 backward error；
- quantize/dequantize 周期与 bytes；
- precision retry 或 numeric failure。

如果量化改变了后续 pivot，应记录实际 pivot，不得使用 FP64 pivot 强行覆盖。局部 INT32/BFP GEMM 尚未实现；接入后必须**重新评估**量化误差经 Schur update 进入父 front 后对 `STATIC` 固定顺序实际主元（`STATIC_PIVOT_FAILURE`/`PIVOT_UNSTABLE` 触发率）的影响。

## 5. 测试矩阵集合

至少包含：

- 可手算小矩阵：验证主元检查、ATU、LU、TRSM 和 Schur；
- 无行交换直接成功（`STATIC`）；
- 只有经过 host 预处理行交换后才能静态成功的矩阵；
- 陷阱矩阵 `[[1,1,0],[1,1,1],[0,1,1]]`：对角非零但消元中途出现零主元；`STATIC` 必须失败，`DYNAMIC_PANEL` 在 panel 内成功；
- 跨 pivot block 主元用例：明确拒绝（`PIVOT_NOT_FOUND`）；
- 近零主元、NaN/Inf 和确定性 tie-break 用例；
- 结构对称、数值非对称矩阵；
- 多根消除森林；
- 稳定随机稀疏矩阵；
- 小主元和高 pivot growth 矩阵；
- front 接近硬件上限的矩阵；
- 多节点和多根森林 `STATIC` 求解，并对原方程做误差检查；
- 非法 map、损坏 descriptor 和地址重叠输入；
- 现有 256/576/1024 规模矩阵。

静态与动态策略分别记录 L/U/P；因子对照只在同一策略内进行，不跨策略比较。

### 5.1 匹配与预处理验证

host 数值预处理（二的幂行均衡 `D_r` + 全局一对一 max-product 加权行匹配）必须验证：

- `P_match`、`Q` 是双射（合法置换数组），组合语义与 manifest 声明一致；
- 匹配覆盖的元素是有效非零（等价对数目标 `sum log|a_j,sigma(j)|`，非 MC64、非逐列贪心）；
- 无完整匹配 → 诊断失败，不产出任何 artifact；
- 变换链语义逐项对照（gather 约定 `y[i] = x[p[i]]`）：
  `B = P_match D_r A`、`A_hat = Q^T B Q`、`b_hat = Q^T P_match D_r b`、`x = Q x_hat`；
- 符号包络在 `pattern(B) ∪ pattern(B^T)` 上重算，ordering/fill/etree/supernode/front/map 全部随变换重算。

### 5.2 置换方向测试

- 使用非对称矩阵 + 非恒等匹配 + 非恒等排序的组合；
- 逐项验证行/列置换方向，gather/scatter 不得取反；
- 参考口径：`graduation-code/software/tests/test_transform_semantics.py`、`test_matching.py`。

### 5.3 负面测试

- 非法策略编码（含 v1 记录 `FRONT_DESC.word8=0`）→ 拒绝；
- schema 版本错误（manifest `abi.version` 不符）→ 拒绝；
- 非法 P-vector 引用（`NONE`、哨兵 `-1`、越界值、全零数组冒充 identity）→ 拒绝；
- 混合格式记录（v1/v2 `FRONT_DESC` 混用）→ `BAD_COMMAND`/`BAD_DESCRIPTOR`。

## 7. 性能实验

性能只在模型边界内报告：

- 总周期和各阶段周期；
- DDR read/write bytes；
- buffer occupancy；
- Panel/TRSM/GEMM busy ratio；
- dependency stall；
- quantize/dequantize overhead；
- serial 与 resource-aware 调度差异；
- tile、lane、带宽和延迟扫描。

不把 SystemC 周期直接写成芯片实测频率或最终吞吐。

## 9. 论文结果标记

每个结果必须标记来源：

```text
HOST_FP64_REFERENCE
SYSTEMC_FP32_DEVICE_MODEL
SYSTEMC_INT32_GEMM_MODEL
RTL_CONTROL_PROTOTYPE
RTL_GEMM_PROTOTYPE（仅在实际存在 RTL 时使用）
```

禁止把行为模型结果、周期估计和 RTL 结果混在同一张表中而不标记来源。

另外禁止：

- 把 `STATIC` 固定顺序失败写成矩阵奇异；
- 在没有硬件速度证据时给出加速比或吞吐宣称；
- 把 `DYNAMIC_PANEL` 的契约表达/参考行为写成设备执行已实现。

  scratch generation 复用、batch 结束后无 lease 残留，树中定向 abort 与
  reset，以及取消前已完成访问仍计入命令统计。响应保持/非法 descriptor/

  模型拍；两者独立 checker 最大误差 `5.273e-8`，检查 16 个节点。
