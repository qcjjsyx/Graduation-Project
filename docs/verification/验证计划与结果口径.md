# 验证计划与结果口径

状态：当前主线文档

## 1. 验证原则

验证必须区分数学正确性、硬件控制正确性、数值格式误差和性能模型。`status=OK` 只表示控制流完成，不表示解的精度达标。

## 2. 五级验证层次

### L0：数学黄金参考

使用 FP64 C++ 验证：

- dense panel LU；
- partial pivoting 和 tie-break；
- TRSM；
- GEMM/Schur；
- 树形前代和回代；
- residual 和 backward error。

### L1：软件产物

验证：

- 原始矩阵数值没有被对称化；
- 符号模式为 `pattern(A) ∪ pattern(Aᵀ)`；
- fill、forest、supernode 和 front 一致；
- 每个原始元素唯一归属；
- map、descriptor、地址和区域不重叠；
- 命令版本、长度和 token 正确。

### L2：SystemC 模块

分别验证：

- CommandFetch；
- GCU scoreboard 和资源调度；
- Buffer/DMA/DDR；
- Assembly；
- HPU；
- ATU；
- Panel-LU；
- TRSM；
- FP32 GEMM；
- `Int32GemmBehavioral`；
- Precision Adapter；
- Solve Controller。

### L3：节点和整树

节点闭环：

```text
LOAD → ASSEMBLE → PANEL → TRSM → SCHUR → STORE → COMMIT
```

整树闭环覆盖：

- 多层 child update；
- 多根 forest；
- 任意任务顺序；
- 父节点等待所有子节点；
- buffer 释放和重新分配；
- factor/update 写回后再读取；
- 前代、回代和 solution 写回。

### L4：RTL/行为接口

如果某个 RTL 模块存在，必须与同接口的 SystemC 模型对照：

- command 接受/拒绝；
- descriptor 解析；
- valid/ready；
- reset；
- backpressure；
- 状态转移；
- pivot、P-vector 或 tile 输出；
- error/status。

没有 RTL 时，L4 对 `Int32GemmBehavioral` 只验证未来 RTL 所需的 transaction contract，不能称为 RTL 验证。

## 3. 数值结果口径

### 3.1 FP64 golden

主要指标：

```text
relative_residual = ||Ax-b|| / (||A|| ||x|| + ||b||)
componentwise_backward_error
relative_solution_error
pivot_growth
minimum_pivot_ratio
```

### 3.2 FP32 SystemC

允许与 FP64 存在浮点误差，但必须报告：

- 最终 residual；
- backward error；
- pivot 差异；
- overflow/underflow；
- 失败节点；
- 周期、bytes 和 stall。

### 3.3 INT32 GEMM 混合路径

不做整树 bit-exact 比较，报告：

- 输入 tile 量化误差；
- GEMM tile 误差；
- Schur update 误差；
- scale、round、saturation 和 overflow；
- 最终 residual 和 backward error；
- quantize/dequantize 周期与 bytes；
- precision retry 或 numeric failure。

如果量化改变了后续 pivot，应记录实际 pivot，不得使用 FP64 pivot 强行覆盖。

## 4. 测试矩阵集合

至少包含：

- 可手算小矩阵：验证 pivot、ATU、LU、TRSM 和 Schur；
- 结构对称、数值非对称矩阵；
- 多根消除森林；
- 稳定随机稀疏矩阵；
- 小主元和高 pivot growth 矩阵；
- front 接近硬件上限的矩阵；
- 非法 map、损坏 descriptor 和地址重叠输入；
- 现有 256/576/1024 规模矩阵。

## 5. 控制和时序测试

- 重复完成同一 token；
- token 下溢；
- child 顺序随机化；
- command ring 截断；
- descriptor version 错误；
- buffer 满/空；
- DMA 延迟和带宽变化；
- HPU backpressure；
- ATU reset、初始化和 swap；
- GEMM K 维分块；
- quantizer 饱和和 overflow；
- timeout 和 abort。

## 6. 性能实验

性能只在模型边界内报告：

- 总周期和各阶段周期；
- DDR read/write bytes；
- buffer occupancy；
- Panel/TRSM/GEMM busy ratio；
- dependency stall；
- quantize/dequantize overhead；
- serial 与 resource-aware 调度差异；
- tile、lane、带宽和延迟扫描。

不把 SystemC 周期直接写成芯片实测频率或最终吞吐。

## 7. 必备结果文件

建议每次运行保存：

```text
summary.json
commands.csv
nodes.csv
operations.csv
timeline.csv
memory.csv
solution.csv
final_memory_image.bin
```

`summary.json` 必须同时包含：

- backend 名称；
- 输入矩阵和 seed；
- 配置与 descriptor schema version；
- correctness 指标；
- precision/overflow/retry 指标；
- cycle/bytes/stall 指标；
- failure reason。

## 8. 论文结果标记

每个结果必须标记来源：

```text
HOST_FP64_REFERENCE
SYSTEMC_FP32_DEVICE_MODEL
SYSTEMC_INT32_GEMM_MODEL
RTL_CONTROL_PROTOTYPE
RTL_GEMM_PROTOTYPE（仅在实际存在 RTL 时使用）
```

禁止把行为模型结果、周期估计和 RTL 结果混在同一张表中而不标记来源。
