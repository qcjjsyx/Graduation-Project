# 多模式 PE 与 16×16 分块计算基线

日期：2026-09-28（2026-10-01 更新状态）。状态：已确认的目标架构，**T06 架构原型、T07 Panel 数值引擎、T09 顶层 TRSM/分组/统一带宽仲裁、T10 顶层 GEMM_Schur（含局部 INT32 行为模型）均已实现**；真实 assemble、树形 solve、RTL、DYNAMIC_PANEL 尚未实现。本文不代表 RTL 综合或性能结论。

## 1. 本次决策与不变契约

- 正式计算架构改为同构、多模式、共享 PE 池。Panel/TRSM/GEMM 是 command controller 和内部任务模式，不再分别配置独立的物理计算池。物理资源唯一按 `compute_group_count × pes_per_group` 配置（`pe_count` 只是与乘积一致的兼容校验字段）：一条计算命令独占一个 PE 组，组内 tile 并行；T09 起生效。
- 主元矩阵 A11 采用固定 16×16 计算 tile，首版各 PE 模式采用同一 tile 边界；不足 16 的尾块携带有效维度和 mask。PE 内部采用任务粒度模拟，时延由明确的数据通路、流水和资源模型推导。
- 保留装配完成后的全 front 扫描、有限值检查与精确 maxabs；暂不做装配融合、历史最大值估计或 Host 尺度注入。所有对角 tile 使用同一个装配后、消元前的固定尺度。
- schema v2 的 32B/64B/64B 布局、FP32 device image、INT32 P-vector、STATIC 实际主元检查和失败传播不变。扫描是尺度归约，不是 HPU 候选搜索。
- 双 front 驻留、默认五个 front/临时/solve 槽、单活动 DMA、顶层同 front 冲突命令保守串行及 completion/token 顺序保留。新增 PE 局部存储单独计容量，不包含在五槽中，也不能隐藏成无限缓存。
- Assemble 是否复用 PE、Solve 的具体复用调度留给后续设计；不得自动把二者解释为已经迁入统一池。DYNAMIC_PANEL 仍由 T14 及后续接入实现，未支持时明确拒绝。

## 2. 数学与任务边界

令 front 阶数 n、主元数 p、更新维度 u=n-p。顶层 PANEL_LU 只修改 A11[p×p]，TRSM_LEFT 生成 U12，TRSM_RIGHT 生成 L21，GEMM_SCHUR 更新 A22。Panel 的尺度扫描必须覆盖整个 n×n front。

A11 内部按 tile 生成 `LU_DIAG / TRSM_LEFT / TRSM_RIGHT / GEMM_UPDATE` 任务：对角 tile 分解，左右 tile 三角求解，剩余 tile 更新。内部任务只作用于 A11，不能重复执行顶层 A12/A21/A22 的工作。推荐首版逐 tile 步设置屏障，不做跨步 lookahead；同一步内互不冲突的任务可并行。

16×16 为计算 tile，不要求 front 或 p 是 16 的整数倍。无效尾元素不得参与 pivot、除法、访存或写回。未来 DYNAMIC_PANEL 的候选范围仍为 k..p-1，不能缩小到当前 16 行。

内部 task 不新增顶层 opcode 或 artifact 格式。现有 descriptor.tile_size 不得静默忽略或重解释：T06 需定义它与物理 tile 的关系。推荐首版真实 backend 只接受 tile_size=16，其他值在能力预检时明确拒绝；通用 codec 与旧 stub fixture 不因此被判为 schema 非法。

## 3. 需要落实的硬件结构

T06 详细设计至少包含：

1. controller、tile task generator、有界队列、局部 scoreboard、共享 dispatcher、PE 池、tile load/store 服务和 command 汇聚完成路径。
2. 每个 PE 的 16×16 阵列、输入 FIFO、目标累加缓冲、有限 task slot、特殊除法/倒数通路、必要的反馈/传播连接及模式控制。明确选定的数据流，不能仅用一段 C++ 循环加任意延迟代替架构。
3. 组数/每组 PE 数（及兼容字段 `pe_count` 的一致性校验）、task slot 数、缓冲字节数、bank/端口、每拍字节、流水 latency/II、请求队列深度的配置与合法性。16 为已决定尺寸，其余首版数值要注明设计假设和理由，不能照搬论文频率/工艺/带宽。设备级统一读/写预算仲裁（每域每拍单请求方 grant）见 TRSM 架构设计 §3.5。
4. 一 PE 同时最多一个计算任务；预取和写回能否重叠取决于实际 buffer/端口。多个 task slot 不等于多个计算阵列。
5. command 对 front 的所有权与内部 tile 访问分层；共享同一 lease 不意味着无限端口。相同目标 tile 更新必须有确定顺序，读后写/写后读及版本就绪由局部调度保证。
6. 双 front 公平性、有界入队背压、有限窗口的推进条件，以及一个 front 内多个 tile 使用不同 PE 的条件。不得依赖无界任务图才能避免死锁。

全 front 扫描建议使用独立读/归约通路，等待尺度有效后才申请计算 PE。扫描的字节、归约延迟、端口竞争和关键路径开销单独报告，不宣称免费。

## 4. 任务粒度模拟的真实性

- 动态建模 request 接受、数据到齐、阵列获得、执行结束、写回完成及响应消费；队列、bank、带宽、端口和 PE 竞争必须真实影响时序。
- 内部固定时延可以由解析模型表示，但须从模式数据流、有效维度、latency/II、装载/排空推导并给出小 tile 事件例证。论文参数只能作参考，不是本项目校准证据。
- 功能计算可在模拟器内部提前完成，结果在预定写回事件前不可见。不能用完整 Host front/reference 对象为设备提供因子或结果。
- LU/三角求解的失败进度具有数据相关性；实际失败列、已完成工作与响应时间须一致，不能全部套完整成功时延。
- 计算写回完成、identity P-vector 写确认、completion 写确认、token READY 的顺序不变。数值失败或 abort 不发布 READY。
- node abort 必须定向到 node/txn；不能取消共享 PE 上另一 front 的任务。已写数据不回滚，仍可能写回的任务在安全结束前不能释放其资源。reset/epoch/generation 拒绝旧结果。
- FP32 是正式设备路径；FP64 模式如保留只用于显式诊断/模块验证，不能暗中替代 FP32 运算。必须说明 FMA/舍入/subnormal、阈值乘积精度及非有限结果处理。

## 5. T06 的编码交付边界

T06 交付详细架构说明、可编译的内部 task/config/response 契约、可执行的时延/任务调度原型及相关测试。原型可用显式合成工作负载验证多模式资源争用、队列、tail 和事件顺序；必须标记为架构原型与 `numerical_validation=not_performed`，不能给正式 command 伪造数值成功。

正式 Panel 数值执行及控制面接入归 T07。Panel 内需要的最小 tile TRSM/GEMM 原语应由 T07 提供可复用实现；T09/T10 扩展与接入顶层 TRSM/GEMM，避免依赖倒置或长期用 stub 通过 Panel 数值验收。T08 在 T07 实现前协调三角求解的共同语义。

T06 不替换当前 T05 的运行 backend，不恢复旧 NodeTask、不实现动态主元、INT32 或完整 solve。不必为了接口/时序原型重构生产调度器；迁移方案必须明确指出现有 TestStubUnit 类型绑定、独立 kind 池、响应汇聚和单元统计如何变更。

packed A11 与持久化 L/U 的关系、STORE_FACTOR 三角 mask/单位对角、容量上限必须在设计中解决或明确列为阻塞 T07 的未决项，不能沿用 stub 的矩形复制来宣称数值因子正确。
