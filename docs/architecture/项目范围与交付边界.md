# 项目范围与交付边界

状态：当前主线文档

## 1. 项目目标

本项目研究面向稀疏方阵求解的多前沿软硬件协同架构。软件负责把全局稀疏结构编译为消除树、supernode、front、映射和执行命令；设备侧负责按照命令执行节点内的局部数值计算、数据搬运和依赖控制。

正式求解对象是：

```text
Ax = b
```

显式求逆不作为主工作负载。若需要 `A^-1`，可将单位矩阵的多列作为多个 RHS，复用同一套因子和求解流程。

## 2. 数学支持域

### 2.1 支持对象

- 方形稀疏矩阵；
- 数值矩阵可以对称，也可以非对称；
- 符号分析使用：

```text
S = pattern(A) ∪ pattern(Aᵀ)
```

- 数值 front、LU、RHS 和 residual 始终使用原始数值矩阵 `A`；
- 使用保守的对称符号包络构造 fill、消除森林、supernode 和 front；
- front、panel、tile、候选主元数量存在明确的硬件上限。

### 2.2 不承诺的数学能力

首版不承诺：

- 完整一般非对称 multifrontal LU；
- delayed pivot 和动态 front 扩张；
- update 行参与 pivot 的任意置换；
- 2×2 pivot、完整 matching 和独立行列 ordering；
- 对所有非奇异矩阵都保证低精度路径成功；
- 任意规模的 front 或任意数量的 RHS。

如果当前 front 内找不到稳定主元，系统必须返回 `PIVOT_NOT_FOUND`、`PIVOT_UNSTABLE` 或 `PRECISION_RETRY`，不能把数值失败伪装成控制成功。

## 3. 三层实现边界

```text
FP64 C++ reference
    ↓ 验证数学正确性
FP32/FP64 SystemC architecture model
    ↓ 验证硬件数据流、时序、依赖和资源
Selected RTL prototypes
    ↓ 验证关键接口和局部硬件状态机
```

### 3.1 FP64 C++ 黄金参考

FP64 C++ 路径只负责：

- dense panel LU、TRSM、GEMM/Schur 和 solve 的数学参考；
- 生成可信 pivot、L/U/P 和 solution 对照；
- 计算 residual、backward error 和解误差；
- 作为 SystemC 输出的 checker。

黄金参考不得向设备路径注入 front、pivot、因子或修正后的结果。

### 3.2 SystemC 架构模型

SystemC 是项目的主硬件模型，必须覆盖：

- command fetch 和 descriptor 解码；
- GCU 调度、依赖 token 和完成状态；
- DDR/DMA 事务、片上 buffer 和生命周期；
- front 装配和 update 写回；
- HPU 主元候选归约；
- ATU P-vector 地址映射；
- Panel-LU、TRSM、GEMM/Schur 和 solve；
- ready/valid、反压、资源占用和周期统计。

SystemC 的数值设备路径以 FP32/FP64 为主。INT32 只在 GEMM 调用边界作为可选混合精度后端。

### 3.3 RTL 原型

RTL 优先覆盖：

- GCU 命令和依赖控制；
- HPU；
- ATU；
- 片上 buffer/SRAM 风格接口；
- 现有或未来的 INT32 GEMM 接口；
- 局部 quantize/dequantize 适配器。

没有 INT32 GEMM RTL 时，使用同一接口的 SystemC `Int32GemmBehavioral` 模块。不能因此暂停整个项目，也不能将 SystemC 行为模型称为 Verilog 验证。

## 4. 六个月交付定义

“完成硬件侧核心模块”在本项目中定义为：

1. SystemC 中所有核心模块都经过显式数据接口和状态机运行；
2. SystemC 完成从命令流、front 装配、分解、写回到求解的闭环；
3. GCU、HPU、ATU 和存储接口形成可运行 RTL 原型；
4. Panel-LU/TRSM 在 SystemC 中完成真实数据通路和周期模型；
5. INT32 GEMM 通过局部量化适配接入 SystemC；
6. 若时间允许，INT32 GEMM 或 quantizer/dequantizer 替换为 RTL；
7. 所有结果区分 FP64 参考、SystemC 设备模型和 RTL/行为后端。

这不是流片级实现，不包含真实 DDR PHY、PCIe、通用 FPGA 驱动和极致吞吐优化。

## 5. 最低验收标准

- 软件产物可被命令解释器读取；
- 单节点和多节点 front 分解正确；
- HPU pivot 和 ATU P-vector 行为可复现；
- SystemC 不通过黄金数据旁路完成设备计算；
- FP32 SystemC 能完成端到端 `A x = b` 验证；
- INT32 GEMM 行为后端能报告量化误差、溢出和转换开销；
- GCU/HPU/ATU 的 RTL 原型可以独立测试；
- 所有数值失败都有明确状态和可追踪日志。
