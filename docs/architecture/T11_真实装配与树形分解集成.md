# T11：真实装配与树形分解集成

状态：2026-10-04，STATIC 分解阶段已实现并验收。求解及原方程 `Ax=b` 验收属于 T12；DYNAMIC_PANEL 接入仍依赖 T14。

## 1. 实施方案与范围

在 T04 数据面、T05 命令/token 执行器和 T07/T09/T10 数值核上补齐真实
`ASSEMBLE_EXTEND_ADD`，形成从输入 artifact 到设备 DDR 因子/update 的节点与
消除树分解链路。执行器只使用 schema v2 的 command、descriptor、map 和
FP32 输入；FP64 参考在设备执行完成后独立计算，不向设备注入 front、因子、
主元或解。

固定本阶段实验配置为 **2 组 × 每组 2 个 16×16 PE 模块**，共 4 个模块。
Panel/TRSM/GEMM 整条命令独占一组，组内并行处理 tile；三类计算复用原有
PanelEngine、TileDispatcher 与 PE 池。`PanelLuConfig.compute_group_count`、
`pes_per_group` 和与乘积一致的 `pe_count` 可配置，本阶段不做规模扫描。
装配使用独立标量加法通路，不新增 PE 池。

首版不引入 lookahead 或复杂调度：最多 2 个驻留 front，5 个 scratch slot
（每个 front 的 front/temp 各一份，另一个保留给 solve）。统一片上读/写预算
默认分别为 64 B/cycle；同一方向每拍仅授予一个 requester，剩余预算不转授。
装配、DMA 与现有数值核共用这个仲裁器。

## 2. 真实 extend-add 数据路径

`AssemblyExecutionUnit` 使用运行时 `ContributionView`。设 child update 为
`d×d`，parent front 为 `n×n`，对所有 `i,j∈[0,d)` 执行：

```text
parent[col_map[i], col_map[j]] += child[row_map[i], row_map[j]]
```

`row_map` 是 child update 源序的排列，`col_map` 是这些 update 变量在 parent
front 中的位置。两张 map 分别同时作用于行和列，沿用既有 schema v2 对称
符号包络契约。多个 child 可映射到同一 parent 位置，依次累加并保留 parent
本地贡献。设备不根据符号树推断或重建映射。

处理顺序如下：

1. DescriptorReader 经设备事务读取 contribution 和 map；检查 parent 身份、
   方形维度、FP32/row-major、源/目标 stride、目标是否为驻留 front、map 长度、
   范围和唯一性。畸形 contribution 在 child 数据 DMA 之前失败。
2. DMA 从 child 的持久 DDR update 读取到 parent temp slot。DDR stride 使用
   REGION_DESC，scratch 中使用紧凑 `d×d`；parent scratch 同样紧凑存储。
3. 获取 temp 读 lease 和 front 写 lease，等待 `ready_cycle`。
4. 每个元素依次经过 `ReadChild → ReadParent → Add → WriteParent`。两次 4 B
   读和一次 4 B 写分别申请统一预算，并实际调用 BufferManager lease 访问。
   加法采用 FP32，默认延迟 1 拍，可通过 `AssemblyConfig` 配置。
5. 最后一次真实写入后返回终态，控制面消费响应后释放 lease。可配置响应保持
   延迟，保持期间单元继续 busy，不能接受新请求。

单元仅保留 child/parent/result 三个 FP32 标量，即 **12 B 数值 staging**；没有
隐藏的整块数值副本。临时 4 B 编解码向量属于一次 scratch 访问的数据载体。
每条 contribution 的装配单元读 `8d² B`、写 `4d² B`，另计 child DMA 的
`4d² B` DDR 读与 scratch 写。默认无争用时每元素经历四个阶段；总命令周期
还包括 descriptor、DMA、lease、completion 延迟和仲裁等待，不是实测芯片周期。

非有限输入或 FP32 加法溢出返回 `NON_FINITE_VALUE`；非法 metadata/lease 返回
`BAD_DESCRIPTOR` 或 BufferManager 的对应错误。不会写入失败元素。此前成功
写入的元素不承诺回滚。

## 3. 树依赖与资源生命周期

```text
NODE_BEGIN（等待所有 child NODE_COMMIT token）
  → LOAD_FRONT（加载本节点本地贡献）
  → 每个 child 的 ASSEMBLE_EXTEND_ADD
  → PANEL_LU → TRSM_LEFT → TRSM_RIGHT → GEMM_SCHUR
  → STORE_FACTOR → STORE_UPDATE → NODE_COMMIT
```

无 child 的节点省略装配；`p=n` 的节点由编译器省略 TRSM/GEMM/STORE_UPDATE。
同一 parent 的 child contribution 按命令依赖串行累加，Panel 等待全部装配。
兄弟节点可按任意合法完成顺序提交，多根 forest 沿用同一 token 执行器。

- child 自己 commit 后可以回收其 scratch front/temp；其持久 DDR update
  留在 artifact 静态分配区中，直到 parent commit 后仍有效，不在 batch 中释放。
- parent 的 front/temp 保留到 parent commit；DMA/数值单元仍持有 lease 时
  不回收。物理 slot 复用使用 slot+generation，防止旧句柄污染新节点。
- 定向 abort 停止后续装配写入，保留已经完成的写入；控制面等待已接收 DMA
  和单元终态排空，再释放资源。取消前实际执行的 scratch 访问仍计入命令统计。
- reset 失效旧 epoch 的事务、响应和仲裁 pending；重新启动后从原始 artifact
  输入执行，不接收旧响应。

## 4. 编译与设备入口

软件新增 `CommandCompilerConfig.emit_solve_commands`（bool，默认 true）和
CLI `--factorization-only`。显式分解模式只省略 solve 命令，保留既有 descriptor
和内存布局，manifest 声明 `compiler.operation_scope=factorization_only`，
不再要求 `tree_solve` 能力。未声明 scope 的旧 artifact 仍按含 solve 的完整
命令链检查。Python/C++ loader 都拒绝 scope 与实际命令不一致的输入。
Command/Descriptor/Completion 的 32 B/64 B/64 B 记录未改变。

`tree_factor_device` 是严格真实后端入口，不允许 test stub 回退。运行时可选择
`FP32_SYSTEMC` 或 `FP32_SYSTEMC_INT32_GEMM`，必须与 artifact manifest 和实际
GEMM descriptor 一致；选择后端不改写已编译二进制。INT32 只影响局部 GEMM，
front、因子、update、装配仍为 FP32，量化参数沿用 T10 manifest/运行时 SCALE_DESC。
超时、后端不匹配、失败命令均以非零退出码结束。

| `final_memory_image.bin` | 完成后的真实设备 DDR 镜像 |
| `summary.json` | 控制、数值状态、后端、资源/仲裁与量化统计 |
| `validation.json` | 外部独立 FP64 checker 结果，单独生成 |

三个结果有不同含义：`control_flow_pass` 表示所有命令正常达到终态；
`numeric_status_pass` 要求真实后端、无 stub 且所有 completion 为 OK；设备自身
仍标记 `numerical_validation=not_performed`。`tree_factor_check` 从不可变初始
FP32 image/map 独立执行 FP64 `factor_front_tree`，比较最终 image 中每节点
完整 L/U/update 和 STATIC identity P-vector，才产生 `numeric_pass`。
矩阵误差定义为 `max|device-reference| / max(1,max|reference|)`，容限 `1e-4`。
checker 不读取 `front_f64.bin` 或预生成 factor/golden 文件。修改最终 L 的负面
测试确认 checker 会拒绝错误结果。求解验收明确为 `not_performed`。

## 6. 验证证据（2026-10-04）

- Release CTest：32/32；ASan+UBSan：32/32（macOS 关闭不支持的 leak detector）；
  Python：120 passed。T11 装配测试 81 checks，树集成测试 1062 checks。
- 12 个结构/输入 × 2 个后端，共 24 个生产编译器 artifact：单节点、两层、
  三层、双 child 重叠累加、双根 forest、非恒等映射/17 维 update 尾块、
  两种迟到 child 身份，以及 3 个固定随机种子的 child 分配顺序。
- 23 个正向 artifact 的所有 L/U/update/P 通过独立 FP64 检查，最大归一化
  误差 `2.636e-7`。全部检查 parent admission 与所有 child commit、Panel 与
  所有装配的依赖，检查 slot generation 复用与 batch 结束后无残留 lease。
- `pivot_propagation` 同一两层树：child 的真实 DDR update 经 extend-add 后，
  FP32 保留 parent 最后主元 `-2^-35` 并通过；局部 INT32 将它量化为 0，parent
  返回 `STATIC_PIVOT_FAILURE`，依赖失败传递到 commit，独立验收明确失败。
  这是 1 个预期失败回归，不是通过样本，也不是实际矩阵总体失败率统计。
- sc_clock 三层树两模式逐拍对照：FP32 1114 拍、INT32 1125 拍，与普通 tick
  模型周期和最终 image 完全相同（该测试默认 DMA 配置不同于树回归配置）。
- 软件完整 CLI smoke：`n=24,density=0.16,max_supernode_size=4`，不执行 host
  reference，生成 16 节点/155 命令。两后端分别 9521/10041 模型拍，全部设备
  状态 OK，独立 checker 检查 16 节点，最大归一化误差均为 `5.273e-8`。
