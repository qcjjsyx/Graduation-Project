## 2. 总体目标

六个月内形成一条可运行、可验证、边界清晰的软硬件协同闭环：

```text
稀疏矩阵 A、RHS b
  → 软件数值预处理（二的幂行均衡 + max-product 行匹配）
  → 软件符号分析/重排/消去森林/supernode/front
  → command stream + descriptor table + data image
  → SystemC Command Fetch/GCU/依赖/buffer/DDR
  → front 装配
  → Panel-LU（默认 STATIC 固定顺序 + 主元检查；DYNAMIC_PANEL 经 HPU/ATU 为可选能力）
  → TRSM
  → GEMM-Schur
       ├─ FP32/FP64 行为后端
       └─ 局部 INT32 GEMM 行为后端
  → L/U/P/update 写回
  → SystemC 前代/回代
  → FP64 checker 和统一实验报告
```

最终交付不是完整流片级浮点 LU，也不是任意规模通用非对称 multifrontal 求解器。必须完成的是：

- 软件可以生成稳定、可校验的结构产物和命令流；
- SystemC 可以通过显式命令、descriptor、buffer 和 memory interface 完成单节点及多节点流程；
- FP64 C++ 是独立数学参考，不冒充硬件周期；
- FP32/FP64 SystemC 是主硬件架构模型；
- INT32 只在 GEMM 调用边界量化和反量化；
- HPU、ATU、GCU/存储控制等关键模块有可独立验证的 RTL 原型；
- 所有数值失败、溢出、饱和、pivot 问题和控制失败都可追踪。

### 3.4 当前执行顺序与阶段验收

2026-09-28 架构更新：采用共享多模式 PE 池、16×16 tile、任务粒度 PE 模拟及保留全 front 扫描，详见 [计算基线](architecture/多模式PE与16x16分块计算基线.md)。T06 增加可编译接口和可执行时序原型，不等于正式数值实现。

- 先推进 T06 STATIC Panel-LU 设计，同时协调 T08 的布局与职责边界；设计评审后推进 T07、T09，接入 T10 的 FP32 GEMM，再形成 T11/T12 的 STATIC 数值闭环。
- T14 后移到上述 STATIC 数值闭环之后，不再作为 T06/T07/T11 的 STATIC 硬前置；DYNAMIC_PANEL 的设计细化、设备接入与验收仍依赖 T14。HPU/ATU 独立模块通过不等于设备动态路径已完成。
- 原 HPU/ATU 任务已重编号为 T14，P0 优先级和原有交付要求保留；T13/T15 仍依赖 T14。T13 可先做不依赖 HPU/ATU 的 RTL 控制工作，但完整验收必须等待 T14。后移不等于取消任务，也不等于已实现动态能力。
- T10 已交付 FP32 与局部 INT32；T11 已补齐真实树执行与受控主元失败传播。
  实际矩阵总体 STATIC 主元失败率仍需后续实验，不由构造回归推断。
- T07/T09/T11/T12 按 STATIC 与 DYNAMIC_PANEL 分阶段记录证据：STATIC 阶段通过不等待动态用例，但不能据此宣称动态验收通过。未实现动态执行时必须返回 `POLICY_NOT_SUPPORTED`，禁止自动退回 STATIC 或 test stub。
- T16 持续覆盖已接入模块；T17 可以先形成 STATIC 实验基线。T18 收口仍需核对全部 P0 交付，不能因 T14 后移而省略；P1 未完成项按原要求明确记录。

## 4. 所有任务的共同工作规则

### 4.1 coding agent 开始前必须做的事

1. 阅读本文件对应任务、当前主线架构文档和目标目录现有代码。
2. 运行一次当前相关测试，记录基线结果。
3. 先说明将修改哪些文件、保留哪些兼容行为、不会修改哪些目录。
4. 如果遇到未冻结的 Panel-LU/TRSM 微架构选择，停止扩大实现范围，先产出设计决策记录。

### 4.2 每个任务的标准交付物

- 源代码或设计文档；
- 自动化测试；
- 至少一个可复现运行命令；
- 运行输出或摘要结果；
- 修改文件列表；
- 已知限制和未完成项；
- 对后续任务的接口影响说明。

### 4.3 必须遵守的限制

- 不读取或写入 `reference_front_f64`、黄金因子或预先计算的 solution 来替代设备路径。
- 不把 `status=OK` 当作数值正确；必须同时报告 residual、backward error、解误差和数值状态。
- 不把 SystemC 行为模型称为 RTL 验证。
- 不将 INT32 scale 扩散为整棵消除树的全局格式。
- 不重新引入 `NodeTask`；设备可见字段进入 descriptor 或 status。
- 不为了通过测试静默吞掉 overflow、saturation、pivot failure 或 dependency error。
- 不修改历史优化分支来“同步当前实现”。当前主线需要时，提取最小逻辑并重新实现。

### 4.4 coding agent 的完成汇报格式

每个任务结束时，要求 agent 按以下结构返回：

```text
任务：Txx
```

### 目标

将软硬件长期交互物固定为版本化 command stream + descriptor table。ABI v2 已完成阶段性验证并归档，不再作为当前输入。

### 依赖

### 参考文档

[Command Stream 与 Descriptor 接口](interface/Command_Stream_and_Descriptor.md)；当前有效位级契约为 [Command / Descriptor Schema v2](interface/Command_Schema_v2.md)（历史版本 [v1](interface/Command_Schema_v1.md) 仅作追溯）。

### 实现要求

1. 按 [Command / Descriptor 固定格式 v2](interface/Command_Schema_v2.md) 冻结 little-endian、32B command、64B descriptor、64B completion、command ID、node ID、descriptor ID 和 wait/signal token 语义。（首版曾冻结 v1，随后按主元策略决定修订为 v2；记录大小不变，v1 仅作追溯与负面测试。）
2. 本版本不在 command record 中携带 `schema_version` 或 `record_bytes`，也不在 descriptor record 中携带 `version`；固定长度和字段语义由本规范及 manifest 区域信息确定。
3. 冻结第一批宏指令：

   ```text
   NODE_BEGIN
   LOAD_FRONT
   ASSEMBLE_EXTEND_ADD
   PANEL_LU
   TRSM_LEFT
   TRSM_RIGHT
   GEMM_SCHUR
   STORE_FACTOR
   STORE_UPDATE
   SOLVE_FORWARD
   SOLVE_BACKWARD
   NODE_COMMIT
   ABORT_NODE
   ```

4. 定义 `REGION_DESC`、`FrontDesc`、`ContributionDesc`、`FactorDesc`、`KernelDesc`、`SolveDesc`、`ScaleDesc`、`DependencyDesc` 和 completion record 的最小字段。
5. 明确 descriptor 只描述数据位置、尺寸、stride、布局和局部 scale，不描述软件内部消除树对象。
6. 冻结控制错误和数值错误的区分：`BAD_COMMAND`、`BAD_DESCRIPTOR`、`ADDRESS_FAULT`、`DEPENDENCY_FAILED`、`POLICY_NOT_SUPPORTED`、`PIVOT_NOT_FOUND`、`PIVOT_UNSTABLE`、`STATIC_PIVOT_FAILURE`、`NON_FINITE_VALUE`、`NUMERIC_OVERFLOW`、`QUANTIZATION_SATURATION`、`PRECISION_RETRY`、`TIMEOUT` 等。
7. 提供 Python 和 C++ 至少一方可读取、校验和打印命令/descriptor 的实现；最好两方共享 golden binary fixture。

### 验收标准

- 相同输入多次生成的 command/descriptor 字节完全一致；
- 截断、版本错误、长度错误、非法 descriptor 引用和 token 错误能够被拒绝；

### 不做

- 不在此任务决定 Panel-LU 内部每个微操作的最终 bit layout；
- 不实现 SystemC GCU；
- 不实现真实 RTL parser。

## T07：Panel-LU SystemC Engine

### 目标

## T12：SystemC Solve Controller 和完整 Ax=b 闭环

### 目标

使求解阶段成为明确的 command 执行过程，读取已提交的 L/U/P/RHS，完成前代、回代并把 solution 写回设备数据区。

### 依赖

STATIC 阶段依赖 T02、T05、T09、T11 的 STATIC 数值分解闭环；P-vector 换行与动态整树用例在 T14 及动态因子路径完成后补充验收。

### 实现要求

1. 实现 `SOLVE_FORWARD` 和 `SOLVE_BACKWARD` command。
2. 前代使用 P-vector 语义处理 RHS（gather 方向 `y[i]=x[p[i]]`，设备局部置换）；不得假设物理行等于逻辑行，也不得混用 host 预处理映射 `P_match`/`Q`（只存在于 host 侧）。
3. 回代按消除树和因子 descriptor 读取已经写回的 U/L；不得读取 golden factor。
4. 结果写入 `SOLUTION_DATA`，再由独立 checker 读取计算 residual。
5. 支持单 RHS；多 RHS 只要接口可扩展即可，不作为首版必须性能优化项。
6. 支持 FP32/FP64 SystemC 数值模式；INT32 GEMM 模式仍使用浮点三角 solve 语义。
7. 记录 forward/backward 的 command、tile、bytes、cycles、stall 和 numeric status。

### 验收标准

- 小型稠密/稀疏树与 T02 golden solution 一致；
- 多级树完成 `Ax=b`；
- P-vector 行交换结果正确；
- 因子缺失、zero diagonal、descriptor 错误和 buffer 不足有明确失败状态；
- 最终 residual、backward error、solution error 可复现。

### 不做

- 不实现 solve RTL；
- 不实现显式逆矩阵专用硬件；
- 不使用迭代求精掩盖基础前代/回代错误。迭代求精只能作为后续可选实验。

- reset、非法 opcode、非法 descriptor、依赖未满足、timeout 可观察；
- RTL 与 SystemC 在短 command trace 上的状态和 token 顺序一致；
- 未实现的 Panel-LU/TRSM/GEMM RTL 不被伪装为已完成。

### 不做

- 不实现完整浮点 Panel-LU RTL；
- 不实现真实 INT32 GEMM RTL（除非用户另行提供 RTL 代码）；
- 不实现 PCIe、AXI PHY、真实 DDR 控制器。

## T14：HPU/ATU SystemC 行为和 RTL 契约统一（后移，未完成）

### 目标

冻结并实现主元选择和逻辑行映射的共同语义，使 SystemC 和 RTL 在边界行为上可对照。HPU/ATU 动态映射属于 **`DYNAMIC_PANEL` 显式可选能力**；默认 `STATIC` 路径在运行时旁路该动态映射（运行时旁路 ≠ 综合时裁剪，两者分别验证和记录）。

### 依赖

技术依赖为 T01、T04，并对齐 T05 的双 front、事务标识和 abort/reset 语义。执行安排后移至 T11/T12 的 STATIC 数值闭环之后；不是 STATIC Panel/TRSM/GEMM/solve 的启动前置。

### 实现要求

#### HPU

1. 输入采用 candidate stream：`valid/ready/value/logical_row/last`。
2. 只实现首版最大绝对值归约和固定 tie-break（并列取最小逻辑行号）；候选范围严格限制在当前 pivot block 行 `k..pivot_dim-1`，跨 pivot block 需求必须明确失败（`PIVOT_NOT_FOUND`）。
3. 输出 `pivot_valid/pivot_ready/pivot_row/pivot_value/fail`，明确空候选、超过最大候选数和 pivot 不稳定状态。
4. SystemC 必须体现收集、归约和输出等待延迟，不得只在一个函数调用中完成全部行为。
5. RTL `hpu_top.sv`、比较树和 testbench 使用同一套边界语义。

#### ATU

1. 维护设备局部 P-vector：INT32、长度 `pivot_dim`、gather 方向 `y[i]=x[p[i]]`、哨兵 `-1` 初始化；`STATIC` 写显式 identity，全零数组永远不解释为 identity；该映射与 host 预处理映射（`P_match`、`Q`）无关。
2. query、swap、init 都使用握手和明确的完成周期。
3. 行交换只修改映射，不搬移 front 数据。
4. Panel、TRSM 和写回访问都必须使用同一个映射语义。
5. 覆盖非法行号、重复 swap、reset 中访问和初始化未完成访问。

### 验收标准

- SystemC/RTL 在相同 candidate、swap、reset 序列上输出一致；
- HPU 覆盖 tie-break、空输入、最大候选数和 backpressure；
- ATU 覆盖 identity、任意 swap、连续 swap、query latency 和非法访问；
- 不支持 delayed pivot、rook、2×2 pivot 时必须返回明确未支持状态。

### 不做

- 不实现复杂 CALU/rook/threshold pivot；
- 不实现动态 front 扩展；
- 不把 HPU 的结果通过黄金参考覆盖。

## T15：SystemC/RTL 事务和 trace 对照

### 目标

即使没有真实 GEMM RTL，也要让 SystemC 和已有 RTL 原型共享可比较的协议和 trace。

### 依赖

T01、T14、T13。

### 实现要求

1. 为短 command stream 生成统一 trace：cycle、module、valid、ready、opcode、node、descriptor、token、status。
2. SystemC 和 RTL 分别导出 trace，不要求每周期数值结果完全相同，但控制事件语义必须可对齐。
3. 对 HPU/ATU 检查 request 接受、输出、swap/query 顺序和 error code。
4. 对 GCU 检查 command decode、dependency wait、resource issue、completion 和 abort。
5. 对不具备 RTL 的 GEMM，只比较 `GemmReq/GemmRsp` transaction contract，不生成 RTL_GEMM 结论。

### 验收标准

- 至少一个 HPU、一个 ATU、一个 GCU 短序列完成自动 diff；
- diff 失败可以指出第一处不一致的 cycle/module/字段；
- trace 结果归档在测试输出目录，不写入历史目录。

### 不做

- 不把 SystemC 周期解释为真实芯片周期；
- 不为了 trace 一致而删除模型中的真实 stall/backpressure。

## T16：分层验证、故障注入和回归测试

### 目标

建立从数学参考、软件产物、SystemC 模块、整树到 RTL 协议的分层验证体系。

### 依赖

T02–T15 按相应模块完成后持续执行；不必等所有任务结束才开始。

### 必须覆盖

1. 软件：非对称数值矩阵、符号包络、fill、forest、supernode、map、descriptor、地址不重叠；host 数值预处理（`P_match`/`Q` 双射、匹配元素为有效非零、无完整匹配诊断、非恒等匹配+非恒等排序下的置换方向）。
2. HPU：空候选、tie-break、最大候选数、pivot unstable、backpressure。
3. ATU：identity、swap、连续 swap、query latency、非法行号和 reset。
4. Panel-LU：1×1、行交换、tail tile、zero/near-zero pivot、overflow。
5. TRSM：左/右 solve、单位/非单位对角、tail tile、zero diagonal。
6. GEMM：全零、正负混合、最大 INT32、K 分块、饱和、overflow、局部 scale。
7. GCU：command 截断、非法版本、未知 opcode、token 重复、buffer 满/空、timeout、abort。
8. 整树：两层/三层、多根森林、随机 child 顺序、buffer 重用和父节点等待。
9. 主元策略：`STATIC` 固定顺序实际主元检查与失败语义（含陷阱矩阵 `[[1,1,0],[1,1,1],[0,1,1]]`：对角非零但消元中途零主元）、`DYNAMIC_PANEL` pivot block 内确定性 tie-break 与跨 pivot block 拒绝、负面用例（非法策略编码、schema 版本错误、非法 P-vector 引用、v1/v2 混合格式）。

### 验收标准

- 软件 pytest、SystemC CTest 和 RTL testbench 有统一入口或清晰入口说明；
- 每个失败用例检查具体状态，不只检查程序返回码；
- 主线回归不能依赖历史 v1/v2/v3 构建产物；
- 因子（L/U/P）对照只在同一主元策略内进行；
- 结果区分 `HOST_FP64_REFERENCE`、`SYSTEMC_FP32_DEVICE_MODEL`、`SYSTEMC_INT32_GEMM_MODEL` 和 `RTL_CONTROL_PROTOTYPE`。

## T17：实验自动化和结果报告

## 6. Panel-LU/TRSM 后续讨论的最小决策清单

在 T06/T08 评审时，优先讨论以下问题。没有结论的项目保持为参数或接口，不由 coding agent 私自固定。主元策略本身已决定：默认 `STATIC`（软件数值预处理 + 硬件固定主元顺序），`DYNAMIC_PANEL` 为显式可选能力；下列标注“（可选能力）”的问题只在实现 `DYNAMIC_PANEL` 时讨论：

### Panel-LU

- panel 是按列串行、按 tile 串行，还是允许有限 lookahead；
- divider 与 reciprocal + multiply 的资源/延迟选择；
- L/U 是否原地存储，还是使用双 buffer；
- （可选能力）HPU 候选收集与 Panel update 是否共享 buffer 端口；
- （可选能力）pivot 行交换是只改 P-vector，还是需要局部数据重排；
- Panel-LU 与 TRSM 的职责边界；
- 首版最大 front、pivot_dim、candidate 数；计算 tile 已确定为 16×16，明确有效维度、tail mask 与 descriptor 能力检查。

### TRSM

- 左解/右解是否统一为一个参数化 engine；
- 对角 tile solve 与非对角 update 的资源划分；
- MAC lane、divider/reciprocal 和 scratchpad 的最小配置；
- solve 阶段是否复用分解内 TRSM 的命令和数据格式；
- tail tile、单位对角、zero diagonal 和失败状态；
- 首版只做 SystemC，还是为未来 RTL 保留精确 transaction wrapper。

这两组讨论的目标不是一次设计出最终最高性能架构，而是先得到一个能被 SystemC 真实执行、被测试验证、未来可替换为 RTL 的最小架构。

## 9. 结论

后续 coding agent 的核心任务不是把旧代码继续补大，而是沿着以下顺序形成可替换的实现层次：

```text
契约 → 软件编译器 → SystemC 设备基础设施
     → Panel-LU/TRSM/GEMM 算子
     → 单节点/多节点/求解闭环
     → RTL 控制原型
     → 分层验证和实验收口
```

Panel-LU 和 TRSM 在架构评审前只实现说明书和接口，不由 agent 擅自决定最终微架构；INT32 只在 GEMM 边界出现；SystemC 必须逐步从 C++ 数值旁路改为显式 buffer/状态机/事务执行。按照此任务划分推进，才能让每个阶段都有独立成果，并且在某个 RTL 模块受阻时不影响整个项目交付。
