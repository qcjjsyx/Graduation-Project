# 树形求解模块设计

实现基准：2026-10-11 当前工作区。
SolveExecutionUnit 从设备 DDR 读取持久 L/U/P、RHS 和变量表，执行单 RHS FP32 前代/回代，
把解写入 solution_data。它使用独立行缓冲与算术通路，共享 DDR 和片上预算，不使用 16×16 PE 池。
数学背景见 [矩阵求解理论](../theory/矩阵求解理论基础.md)，坐标变换见
[软件侧技术文档 §3.2](../software/软件侧技术文档.md#32-坐标变换与置换约定)。

## 1. 架构与调用关系

```text
CommandDevice → DescriptorReader：SOLVE_DESC / FACTOR_DESC / region / g payload
  → 获取 solve scratch 容量预留、选择 SolveExecutionUnit
  → SolveExecutionUnit：P-vector → 向量 gather → 因子行读取 → 行计算 → scatter 写回
       ├─ MemoryService：有限 DDR 请求、request_id 响应归属
       └─ OnChipArbiter：局部暂存写预算、计算消费读预算
  → 全部写确认 → 唯一 ExecResponse → completion 写确认 → token
```

正式 tree_factor_device 启用 enable_real_solve 与一个 Solve 单元。
软件默认 scope 为 factorization_and_solve，factorization_only 不发求解命令。
所有数值输入来自设备区域，单元不访问任何 FP64 golden/reference 文件。

## 2. 数据契约

### 2.1 坐标、因子与变量表

设备求解变换后的系统 `Â x̂=b̂`。rhs_data、solution_data 均按 Q 序全局变量编号索引；
host 用 `x[ordering_perm[i]]=x̂[i]` 恢复原变量顺序。
行缩放、匹配和 Q 的构造在软件侧完成，求解单元不重复执行这些变换。

节点 front 维 n，pivot 维 p，update 维 u=n-p：

| 数据 | 约定 |
|---|---|
| factor_l | `n×p` FP32，前 p 行 L11 显式单位下三角，后 u 行 L21 |
| factor_u | `p×n` FP32，前 p 列 U11 显式上三角，后 u 列 U12 |
| p_vector | p 个 INT32；pivot 位置 i 的 RHS 行来自 pivot block 内 P[i] |
| g payload | n 个 u32 全局变量号，前 p 个是本节点连续递增 pivot 范围，后 u 个为 update 变量 |
| rhs_data | 全局 b̂，只读 FP32 |
| solution_data | 初始全零的工作向量 w，最终为 x̂ |
| workspace | 每节点 `2×p` FP32，第 0 行保存前代 z；第 1 行当前不承载正式结果 |

SOLVE_DESC 记录布局以 [schema v2](../interface/Command_Schema_v2.md) 为准。
g payload 必须四字节对齐、大小 `4*n`、无重复、所有值小于全局 N，pivot 前缀满足节点范围。
descriptor、引用和形状由 loader/reader 检查，单元还校验运行时请求及 P-vector。
P-vector 必须是 `[0,p)` 的排列；-1 表示尚无成功因子，但任何非法排列都返回 BAD_DESCRIPTOR。

### 2.2 前代与回代

前代按 child 先、parent 后的 factorization_order 执行：

```text
对 i∈[0,p)：r_i = b̂[g[P[i]]] + w[g[P[i]]]
L11 z = r                          # 单位下三角，递增行
对 t∈[0,u)：w[g[p+t]] -= Σ_j L21[t,j]*z_j
对 i∈[0,p)：w[g[i]] = z_i
workspace 第 0 行 = z
```

本节点前代开始前，其后代已把对相同祖先变量的贡献写入 w。
pivot 写入 z 后，w 的 update 段仍作为祖先累加器；rhs_data 不修改。
P-vector gather 同时用于 RHS 与该 pivot block 的累加贡献。

回代按相反顺序执行，update 变量对应的祖先解已经可用：

```text
对 i∈[0,p)：c_i = w[g[i]] - Σ_t U12[i,t]*w[g[p+t]]
U11 x = c                          # 非单位上三角，递减行
对 i∈[0,p)：w[g[i]] = x_i
```

设备读、算、写为 FP32；源码使用 `value -= a*b` / `accumulated += a*b` 等 float 表达式，
没有显式调用 std::fma，乘加是否融合受编译器影响。回代对角用 FP32 除法并检查零与非有限。
局部 INT32 GEMM 不改变本单元的精度。host 参考可用不同累加器初始化，但需保持数学等价。

## 3. 命令依赖与失败传播

编译器按 factorization_order 输出 forward 链，按其逆序输出 backward 链。
每个 forward 等待本节点 NODE_COMMIT，除首项外还等待前一 forward；
每个 backward 等待本节点 NODE_COMMIT 和前一 solve，首项等待最后一个 forward。
单条 wait list 最多两个 token，与节点数无关。

设备把求解 Tracker parked 至所有 NODE_COMMIT 已得到终态，不计入窗口额度。
这个门控只保证分解阶段的调度空间；真正的失败判定来自本命令的 wait token。
失败的 commit 也计入门控计数，不能让整批永远等待。

若某节点分解失败，链上更早的 forward 可能已成功；从遇到失败依赖的 forward 起传播失败，
backward 链也失败。部分 workspace/solution 字节可能存在，但不能当作有效解。
设备 numeric_status_pass 为 false，求解 checker 要求所有 solve completion 为 OK。

求解链串行，避免兄弟节点对同一祖先变量执行并发读改写而丢失贡献。
多个独立根仍沿用同一全局求解链；当前实现没有并行树形 solve。

## 4. 有限行缓冲与 DDR 访问

### 4.1 状态与请求归属

单元状态依次为 `PVector → VectorReads → UpdateReads → Rows → Writes`。
每个 DDR 请求携带有限长度和唯一 request_id；pending 表记录请求类型、局部起点、行号和元素数。
`handles_request` 精确识别响应，只有当前 epoch 和当前事务的响应能推进状态。
MemoryService 队列满时保留进度，下拍重试；终态等待自身全部已接受请求排空。

update 段 gather/scatter 根据 g 合并连续全局地址，再按 max_elements_per_request 分块；
非连续段分开请求。P-vector、连续 pivot RHS/w、workspace 和 pivot 写回以本节点 p 个元素为一块，
因子按整行发请求；请求规模受节点维度与行缓冲容量约束，不读取整份全局向量。
L 前代按 n 行、每行 p 元素流式处理；U 回代按 p 行、每行 n 元素处理。
row_buffer_depth 限制同时存活的行，可在容量允许时预取后续行。

### 4.2 容量与片上预算

默认配置：

| 参数 | 值 | 作用 |
|---|---|---|
| lanes | 16 | 点积每拍有效乘加元素数 |
| reduce_latency | 2 | 点积归约延迟 |
| div_latency | 4 | 回代对角除法延迟，独立于 PE 的倒数通路 |
| row_buffer_depth | 2 | 有限因子行缓冲 |
| max_elements_per_request | 64 | update 段单次 DDR gather/scatter 元素上限 |

scratch 容量上界由 `SolveExecutionUnit::scratch_bytes` 定义：

```text
4 * (row_buffer_depth*n + 2*n + p) 字节
```

它覆盖因子行缓冲、z/x、update 向量和 P-vector。控制面在共享 solve scratch 槽获取写 lease 预留容量。
活跃向量为单元内部的有限存储；DDR 响应已直接到达本单元，不再经 BufferManager 复制同一批字节。
暂存按 OnChipArbiter 写域计费，计算读取按读域计费；lease 预留保证容量，预算保证带宽。

统计模型对长度 m>0 的点积计 `ceil(m/lanes)+reduce_latency`，m=0 时计 0，回代另加 div_latency。
当前 process_row 在本行读预算满足后同步计算，并把成本累加到 compute_cycles；
它没有按这个成本延迟状态机的下一行、输出写请求或 poll。终态响应的 finish_cycle 写为
`max(当前周期, 最后写确认周期, start_cycle+compute_cycles)`，该时间戳可以晚于实际响应消费。
控制面直接消费响应，不等待这个 finish_cycle。

因此 compute_cycles 是算术成本统计，units.csv 的求解结束字段包含推导时间，
实际 batch/completion 周期主要由 DDR、行预取、预算和写确认推进；它们还不是一致的完整算术时序模型。
性能分析需区分这些口径。staged_bytes/consumed_bytes 与 DDR 流量仍按真实访问记录。

## 5. 终态、取消与 reset

| 条件 | 行为 |
|---|---|
| 非法 view、变量表或 P-vector | BAD_DESCRIPTOR |
| 回代 U 对角为零 | STATIC_PIVOT_FAILURE |
| 输入、乘加或除法结果非有限 | NON_FINITE_VALUE |
| scratch 硬容量不足 | BUFFER_FULL |
| DDR 请求错误 | 相应访存终态，停止后续工作 |
| 定向 abort | 停止新工作，排空已接受访存，唯一终态 ABORTED |
| 全局 abort_epoch/reset | 清状态及旧响应，旧 epoch 失效，不再为旧请求生成可消费终态 |

输出 scatter、workspace 和 pivot 段写回均需确认，之后才提供 ExecResponse。
控制面再写 completion 并发布 token。已发生的写不回滚；失败命令不得发布 READY。
响应生成后、poll 前收到匹配 txn 的 abort，应保留同一个响应并转为 ABORTED，重复取消幂等。

## 6. 执行入口与重复求解约束

正式入口是 tree_factor_device 的 factorization_and_solve 或 factorization_only 批次。
目前没有正式的“加载已存因子后仅发 solve”CLI，也没有设备修正步的 host 迭代求精循环。
rhs_data 只读、solution_data 零初值和因子持久化是重复求解所需的数据约定，
但仅重新写 RHS/清零 w 不等于已有完整重放接口；还需重新建立命令、token、completion 和设备状态。
相关后续工作见 [todo](../../todo.md)。

## 7. 独立 checker 与实现入口

tree_solve_check 从初始 artifact 和 final_memory_image.bin 独立读取数据，核查全部求解终态、
workspace 前代关系、因子回代关系，以及变换后和原方程的数值指标。
默认三角求解后向误差容限为 1e-4；通过条件包含所有 solve 为 OK 以及 eta_forward/eta_backward 达标。
原方程残差、后向误差和解误差会报告，不自动作为上述三角求解门槛。
病态矩阵可能有小后向误差和大解误差，需结合条件数解释。
