# 装配与因子保存设计

实现基准：2026-10-11 当前工作区。
本文定义节点本地贡献、child update、front、完整因子和 DDR 输出之间的实际数据路径。
数学上的 extend-add 见 [矩阵求解理论](../theory/矩阵求解理论基础.md)；
地址、lease 和 DMA 契约见 [数据面设计](数据面设计.md)。

## 1. 架构与节点执行关系

```text
本节点 DDR 本地贡献 ──LOAD_FRONT/DMA──> front scratch
child DDR update ──DMA──> parent temp ──AssemblyExecutionUnit──> parent front
parent front ──Panel/TRSM/GEMM──> packed A11 + U12 + L21 + Schur update
  ├─FactorStoreUnit──> DDR 完整 L/U
  ├─控制面 P-vector 写──> DDR P
  └─STORE_UPDATE/DMA──> DDR update
所有保存命令收尾 ──NODE_COMMIT──> 回收 front/temp，发布 token
```

NODE_BEGIN 等待所有 child NODE_COMMIT token；成功后分配 front/temp。
LOAD_FRONT 初始化本地贡献，装配串行叠加 child contribution，然后进行数值分解。
无 child 时省略装配；`p=n` 时编译器省略顶层 TRSM/GEMM/STORE_UPDATE。
STORE_FACTOR 和 STORE_UPDATE 的具体依赖由编译器生成，设备仍对同一 front 保守串行。

## 2. extend-add 的接口和映射

AssemblyExecutionUnit 使用运行时 ContributionView。child update 为 `d×d`，
parent front 为 `n×n`，对 `i,j∈[0,d)` 执行：

```text
parent[col_map[i], col_map[j]] += child[row_map[i], row_map[j]]
```

row_map 是 child update 源序的排列；col_map 是这些变量在 parent front 中的位置。
两张映射分别作用于行和列，沿用 schema v2 的对称符号包络。
当前编译器通常输出 identity row_map，设备按照 payload 执行，支持合法源排列。
不同 child 可贡献到同一 parent 位置，依次累加并保留本地贡献。

DescriptorReader 经设备事务读取 contribution 与 map；检查 parent 身份、当前驻留目标、
方阵、FP32 row-major、两侧 stride、map 长度、范围和唯一性。
畸形 metadata 在 child 数据 DMA 前失败，设备不根据 host 消除树补推映射。

## 3. 装配数据通路与周期

1. DMA 从持久 child update 读取到 parent temp。DDR stride 由 REGION_DESC 表达，temp 为紧凑 `d×d`。
2. 控制面获取 temp 读 lease 和 front 写 lease，单元等待 ready cycle。
3. 每个元素依次经过 `ReadChild → ReadParent → Add → WriteParent`。
4. 两次 4 B 读和一次 4 B 写分别申请统一片上预算，并实际调用 lease 访问。
5. 最后一次写入后提供唯一终态；控制面消费响应后释放访问资源。

单元只保存 child/parent/result 三个 FP32 标量，数值 staging 为 12 B。
AssemblyConfig 默认加法延迟 1 周期、响应保持 0；响应保持期间仍 busy。
装配单元成功流量为读 `8*d*d`、写 `4*d*d` 字节；child DMA 的 DDR 读和 scratch 写各 `4*d*d`，另行统计。
总命令周期还包含 descriptor、DMA、lease、仲裁和 completion 延迟。

输入非有限或 FP32 加法溢出返回 NON_FINITE_VALUE；失败元素不写入。
先前已成功累加的元素保持，当前实现没有 contribution 原子回滚。

## 4. 完整因子布局

front 阶数 n，主元维 p，更新维 u=n-p。STORE_FACTOR 使用 FactorView 的地址和 stride，
保存显式矩形因子：

| 区域 | 形状 | 来源与补齐规则 |
|---|---|---|
| factor_l | `n×p` FP32 | 前 p 行：A11 严格下三角、对角补 1、上三角补 0；后 u 行：L21 |
| factor_u | `p×n` FP32 | 前 p 列：A11 上三角含对角、下三角补 0；后 u 列：U12 |
| p_vector | `p` INT32 | Panel 成功后控制面写入；STATIC 为 identity |
| update | `u×u` FP32 | GEMM 完成后的 A22；由 STORE_UPDATE 保存 |

L21/U12 必须是顶层 TRSM 的计算结果。不能仅保存 A11 或把尚未求解的 A12/A21 写成完整因子。
gather 置换只作用于 pivot block 内的行；STATIC 当前没有实际行交换。
求解读取这些持久区域，而非已经回收的 front scratch。

## 5. FactorStoreUnit 的按行写回

控制面授予 front 读 lease，FactorStoreUnit 按行读取有效元素并转换显式 L/U。
局部暂存以一行数据为单位，不复制整个 front；读取按 FactorRead 统一预算分段。
构造行后分别经 MemoryService 写入 L 与必要的 U 行，DDR stride 与紧凑 front stride 独立。

`l_submitted_`、`u_submitted_` 记录当前行哪一侧已被内存服务接受。
一侧成功、一侧背压时保留暂存和提交标记，只重试尚未接受的请求。
响应按 request_id 精确归属，完成前等待本事务所有已接受写确认。
新事务、行推进、终态与 reset 按各自状态清理提交标记，不能重复写上一行。

成功写入 L/U 的字节为 `8*n*p`；Panel P-vector 的 `4*p` 字节独立计入 PANEL_LU。
该保存单元不重新分解、不读取参考因子，也不把输出通过 DMA 重复搬运。

## 6. STORE_UPDATE 与存储生命周期

STORE_UPDATE 从 front 的 A22 子区域读取，经 DMA 写入 descriptor 指定的持久 update。
起点为 front 行列 p，片上 stride 为 `4*n`，DDR stride 使用 update REGION_DESC，可带 padding。
成功有效载荷为 `4*u*u` 字节；无更新维时编译器省略命令。

child commit 后，其 front/temp 可回收，但 DDR update 仍保留在镜像静态分配区。
parent 装配不依赖 child scratch 的继续驻留。parent 自身槽保持至 commit，且不得有活动 lease、DMA 或单元引用。
物理 slot 复用使用 generation 检查，防止旧句柄作用于新节点。

completion 写确认后才发布保存命令 token；NODE_COMMIT 必须等待保存结果。
已完成写、completion 确认和 token 发布是不同事件。

## 7. 错误、取消和 reset

非法 descriptor、映射或范围返回相应终态；硬容量不足返回 BUFFER_FULL。
暂时端口竞争和内存队列满产生背压，不能当成永久容量错误。
数值或访存失败后停止新工作，排空已接受请求，保留唯一终态。

定向 abort 丢弃未提交工作，已接受的 DDR/DMA 请求自然排空；排空后终态 ABORTED，
再释放 lease 和槽。此前落实的写入保留，因此失败因子/update 不可当作有效结果。
全局 reset 失效旧 epoch、句柄、响应和 pending 仲裁请求，不撤销 DDR 写，也不重载初始 artifact。
