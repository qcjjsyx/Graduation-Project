## 2. B01：abort 删除待取的立即错误响应，设备批次永久挂起

### 触发、影响与定位

1. 使用合法两层树 artifact，把 cmd 3（TRSM_LEFT）的 descriptor 中 M 改为 2；该 fixture 的 pivot_dim 为 1，因此这是运行期形状错误。
2. artifact loader 接受字节布局；TRSM adapter 正确产生 BAD_DESCRIPTOR 的立即响应，并向控制面报告请求已接受。
3. 在下次控制面 poll 该响应之前，对 node 0 调用 `abort_node(0)`。
4. `TrsmExecutionUnit::abort_txn` 删除 `immediate_`，而该请求从未进入 engine，engine 不可能再产生替代终态。
5. 控制面仍持有 `unit_active`，按“取消后等待在途访问排空，再由终态响应释放资源”的约定等待。cmd 3 永远停在 Running，最终只写出 14/15 条 completion。

直接根因在 [panel_exec_unit.cpp:350](../graduation-code/systemc/src/controlplane/panel_exec_unit.cpp#L350) 的 `TrsmExecutionUnit::abort_txn`（修复前约第 304 行）：匹配 txn 后执行 `immediate_.reset()`。等待端是 [control_plane.cpp:1914](../graduation-code/systemc/src/controlplane/control_plane.cpp#L1914) 的 `CommandDevice::abort_node`，其中 `unit_active` 分支有明确的终态响应排空约定。错误形状本身被拒绝是正确行为；**拒绝与 abort 相遇后不再终止**才是缺陷。

`PanelExecutionUnit`、`GemmExecutionUnit` 也存在相同的 immediate 清空写法，本报告的完整设备复现针对 TRSM_LEFT；修复时已把 Panel/TRSM/GEMM 三条 adapter 路径以及 `FactorStoreUnit`、`TestStubUnit` 的待消费终态删除一并修正（见下节），未把未经同样复现的路径列成额外已确认缺陷。

### 测试为什么没抓到，以及最小修复建议

当前回归分别覆盖非法 descriptor 和正在真实执行的事务取消，但没有交叉覆盖“adapter 已接受、立即错误响应尚未被控制面取走”的窄窗口。一般执行后再 abort 的测试进入 engine 的排空路径，因此不会丢失终态。

最小修复方向：保留待取的 `immediate_`，将其转为该 txn 的唯一 ABORTED 终态，或者按明确约定保留已确定的错误终态；不能直接删除。保证一次接受恰好对应一次可取终态。对 Panel/TRSM/GEMM adapter 的同类代码统一核查。不要通过无条件提前释放 tracker 来绕过等待，否则真实在途写回可能污染已复用的 front。

应补两层回归：adapter 层 `submit(非法 shape) → abort_txn → poll` 必须返回一次终态且之后为空；设备层上述两层树必须有限拍完成，所有命令完成、front 释放、scratch lease 无残留。

### 修复与终态语义（2026-10-07）

修复以上述最小方向落地，入口是执行单元的终态响应生命周期，不跳过非法 descriptor、不加超时、不强制 completed、不忽略 `unit_active`：

| 修改点 | 位置 | 行为 |
|---|---|---|
| `PanelExecutionUnit::abort_txn` / `TrsmExecutionUnit::abort_txn` / `GemmExecutionUnit::abort_txn` | [panel_exec_unit.cpp:167](../graduation-code/systemc/src/controlplane/panel_exec_unit.cpp#L167)、[350](../graduation-code/systemc/src/controlplane/panel_exec_unit.cpp#L350)、[559](../graduation-code/systemc/src/controlplane/panel_exec_unit.cpp#L559) | 匹配 txn 的待消费 `immediate_` 不再 `reset()`，就地转为同一 txn 的 ABORTED 终态 |
| `FactorStoreUnit::abort_txn` | [panel_exec_unit.cpp:893](../graduation-code/systemc/src/controlplane/panel_exec_unit.cpp#L893) | 同上：submit 拒绝或已产出未消费的 `response_` 终态不被删除 |
| `TestStubUnit::abort_txn` | [test_stub_unit.cpp:184](../graduation-code/systemc/src/controlplane/test_stub_unit.cpp#L184) | 原实现删除 `response_` 后若 `active_` 已空则不再补终态（与自己的注释矛盾）；改为就地转 ABORTED 并立即可取 |
| 三类 engine adapter 的 `active_command_id` 诊断 | [panel_exec_unit.hpp](../graduation-code/systemc/include/controlplane/panel_exec_unit.hpp) | 补齐接口既有语义（已接受未消费 txn 的 command id），供设备层回归确定性命中响应窗口，不新增生产接口 |

**明确的终态语义：** 请求被接受后恰好产生一个可消费终态；若该终态尚未被控制面取走时发生 abort，**保留响应对象并转换为同一 txn 的 ABORTED 终态**，txn/command/node/epoch/unit 身份与字节、周期等统计保留，`needs_pvector_write` 清除（取消不得触发成功输出写）。选择 ABORTED 而非保留原错误的代码依据：`AssemblyExecutionUnit::abort_txn`（[assembly_exec_unit.cpp:184](../graduation-code/systemc/src/controlplane/assembly_exec_unit.cpp#L184)）本就把待消费响应转为 ABORTED；控制面 `handle_exec_response` 对 aborted tracker 本就统一以 `Aborted` 结束并写 ABORTED completion，转换后 adapter 与设备契约一致。abort 不匹配的 txn 不删除、不修改当前响应；重复 abort 幂等；终态被消费后不再返回，completion 与 token 各只写一次（`finish_command`/`drain_completion_results` 的单次终态守卫未变）。

**为什么不提前释放、也不会重复终态：** abort 仍只是“请求取消”。真正进入 engine / DMA / DDR 写回的事务走原有排空路径（engine `aborting` + controller `request_abort`、Factor `pending_ids_` 清空后才 `finish_terminal`、DMA job 结算计数），`abort_node` 在 `unit_active` 时继续等待唯一终态后才 `release_command_resources`，`maybe_cleanup_node` 仍只在节点终态后释放 front；失败/取消不发成功 token（token FAILED），父节点准入依赖 commit token 因此不会错误准入。reset 的 epoch 隔离与旧响应清理（`abort_epoch`/`reset` 的 drop 语义）保持不变，未与 abort 混同。engine 与 controller 路径本就不丢终态（只排空），故未改动。

**回归覆盖（全部进入仓库现有测试组织）：**
- adapter 层 A：`trsm_real_tests.cpp::test_immediate_terminal_survives_abort`（TRSM 形状拒绝 + adapter 操作数拒绝两个立即分支）、`gemm_real_tests.cpp::test_immediate_terminal_survives_abort`（GEMM shape/operand 拒绝）、`panel_lu_real_tests.cpp::test_immediate_terminal_survives_abort`（Panel engine 拒绝 + FactorStore submit 拒绝与真实工作产出终态后 abort 未消费两种窗口）、`controlplane_core_tests.cpp::test_stub_unit`（response hold 窗口）。均覆盖：poll 前同 txn abort 取到恰好一个 ABORTED 终态、之后 poll 为空、单元不再 busy、重复 abort 无重复响应、不匹配 txn abort 不删除/不修改当前响应。
- 设备层 B：`tree_real_tests.cpp::abort_immediate_error` 保留 two_level/fp32 场景（cmd 3 TRSM_LEFT descriptor M 改 2，内存内修改），用 `unit_active_command_id` 确定性命中“已接受、立即错误未 poll”窗口后对 node 0 连续两次 `abort_node`（幂等），并同时跑无 abort 对照；断言有限拍正常收尾（非 timeout fault）、每命令恰好一条 completion、目标命令终态语义（无 abort=BAD_DESCRIPTOR，abort=ABORTED）、依赖父节点不发布成功、取消不发成功 token、front 释放、active lease 归零、scratch 可复用。
- 已有语义 C 复用未重复堆叠：运行中真实计算/写回 abort 排空（`panel_lu_real_tests.cpp::test_abort_waits_for_engine_drain`、`test_factor_abort_reuse_clears_partial_row`、`trsm_real_tests.cpp::test_abort_trsm_and_reuse`）、reset 后旧事务隔离（`tree_real_tests.cpp::abort_reset`、`panel_lu_real_tests.cpp::test_reset_and_restart`、stub `abort_epoch`）、正常 FP32 与局部 INT32 GEMM 树分解回归（`tree_real_tests` / `tree_factor_device_*` / `gemm_real_tests`）。

## 3. B02：HPU 输出 valid 未在握手时清除，结果重复提交

### 根因与影响

[hpu_top.sv:90](../graduation-code/hardware/HPU/hpu_top.sv#L90) 在 OUT 的 `pivot_valid && pivot_ready` 成立后转 IDLE；但 [hpu_top.sv:137](../graduation-code/hardware/HPU/hpu_top.sv#L137) 对应时序分支的 `pivot_valid_r <= 1'b0` 被注释。valid 到后续 IDLE 时序分支才清除，所以两个连续时钟沿都满足 valid/ready。下游按标准 ready/valid 契约会接受两次同一个主元结果，可能重复 swap 或推进控制状态。

### 最小复现与工具边界

Icarus 对原始 `hpu_core_tree.sv` 的 struct-array 展开发生内部 assertion（`elab_expr.cc:2677`，源码触发点约第 54 行），因此本次没有获得完整 HPU 的原样仿真结果。为隔离输出握手，使用下列确定性 core 替身，**被测 hpu_top.sv 保持原样**。替身只提供一个稳定合法结果；该复现证明 top 的协议问题，不证明实际比较树数值逻辑。

## 4. B03：ATU 同时接受 cfg 与 pivot，但只执行 pivot

### 根因与影响

[ATU.sv:157](../graduation-code/hardware/ATU/ATU.sv#L157) 的 `pivot_req_ready` 与 [ATU.sv:189](../graduation-code/hardware/ATU/ATU.sv#L189) 的 `cfg_ready` 都仅由 init_state==IDLE 决定。两路同时有效时，双方都看见接受条件成立；但 [ATU.sv:174](../graduation-code/hardware/ATU/ATU.sv#L174) 的时序写口先处理 pivot，cfg 位于 `else if`，没有执行也没有排队。
