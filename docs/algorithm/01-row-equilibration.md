# 01 行均衡（2 的幂行缩放）

代码：`graduation-code/software/src/equilibration.py` · 配置：`EquilibrationConfig`

## 1. 要解决的问题

一般稀疏矩阵的行在量级上可能相差几十个数量级：某行元素全在 `1e-20`，
另一行全在 `1e20`。这会带来三类后果：

1. **FP32 设备路径溢出/下溢**：消元中的乘子、Schur 更新是行间数值的乘积与差值，
   量级差会在 FP32（指数范围约 `2^±127`）里直接产生 Inf/0。
2. **主元阈值失去可比性**：静态主元判据是相对阈值
   `|pivot| <= threshold_ratio * front_pre_elimination_max_abs`，
   行尺度悬殊时同一条阈值在不同行上含义完全不同。
3. **pivot growth 与舍入误差放大**：不均衡系统的消元中间量增长更难控制。

匹配（见 02）只解决"对角有没有非零"的**结构**问题，行均衡解决的是**数量级**问题，
两者不可互替。

## 2. 算法

对每行取绝对值的最大值

```text
r_i = max_j |A[i, j]|
```

选一个 2 的幂做缩放因子：

```text
e_i = clip( -round(log2 r_i), -E, +E )      E = max_scale_exponent（默认 60）
D_r = diag(2^{e_i})
D_r A x = D_r b
```

- `round(log2 r_i)` 使缩放后每行最大值落在 `[1/√2, √2] = [2^{-0.5}, 2^{0.5}]`：
  2 的幂只能把数量级搬到最近的整数指数上。
- 缩放同时作用于右端：`b ← D_r b`。
- **没有列缩放**，所以数学解 `x` 不变，求解后**无需恢复**。

## 3. 为什么是"行 + 2 的幂"

- **只缩放行**：`D_r A x = D_r b` 是等价变形（左乘可逆对角阵），解不变。
  若缩放列（`A D_c y = b, x = D_c y`），解空间改变、需要恢复变量，还要同步
  manifest/checker；本次范围明确排除列缩放。
- **2 的幂是精确操作**：乘 `2^e` 在浮点中只改指数、不动尾数，不引入舍入。
  硬件数据通路可实现为 exponent 偏移而非乘法器。
- **可无损记录与复现**：`D_r` 只需要 `int16` 指数数组（`row_scale_e.bin`），
  同输入完全可复现。
- **单次、无迭代**：不做 MC64 风格的多轮缩放/对偶势迭代，保持行为可解释。

## 4. 重要不变量

### 4.1 与匹配的交换性

对任意完美匹配 `σ`：

```text
∏_j |(D_r A)[j, σ(j)]| = (∏_i d_i) · ∏_j |A[j, σ(j)]|
```

右端常数因子 `∏_i d_i` 与 `σ` 无关 ⇒ **行缩放不改变最大乘积匹配的最优解集**
（浮点并列情形除外）。因此"先缩放后匹配"还是"先匹配后缩放"在数学上等价；
pipeline 选择先缩放后匹配，以便记录真正进入后续阶段的数值系统。

### 4.2 精确性与 FP32 表示

- 缩放发生在 FP64→FP32 转换之前；转换是唯一有舍入的步骤，而它相对误差
  `≈2^-24` 与指数无关（幂缩放只改指数）。
- 对原本 `< 2^-126`（FP32 subnormal）的行，放大后反而**保留**了完整尾数；
  对原本 `> 2^127` 的行，缩小后避免 Inf。均衡可以严格改善 FP32 可表示性。
- 缩放后的数据才是写入设备 image 的数据；host 侧 FP64 参考使用同一缩放系统，
  残差/后向误差最终对**原始** `Ax=b` 计算。

## 5. 边界与限制

- 只治**行间**量级差；行内跨 `1e±30` 或列间量级差不受影响。这类矩阵在静态
  路径上仍可能表现为小主元/阈值拒绝/高 pivot growth。
- 截断到 `±E`（默认 60）意味着极端行的残余动态范围保留原样；这是有意的保护
  （避免把行搬到 FP32 指数极限）。
- 缩放不修结构零、不保证静态消元成功。
- 空行（`r_i = 0`）不缩放，`e_i = 0`。
