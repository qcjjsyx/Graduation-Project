本实验以设备 FP32 因子在 host 上做 **FP64 三角求解与三步修正**。
它与 [精度边界实验](../precision_boundary/实验报告.md) 的 **FP32 三角修正步**不同，

## 1. 问题

仓库自带的三个真实矩阵（`example/256X256JJ.mat`、`576X576JJ.mat`、`1024X1024JJ.mat`）跑完整主线
（编译 → `tree_factor_device` FP32 STATIC → `tree_factor_check`）时，设备所有命令状态都是 OK，
但 checker 判定失败。checker 逐元素比较设备的 L/U/update 与同一输入的 FP64 分解，容限 1e-4：

| 矩阵 | 编译选项 | 设备 | checker 最大相对误差 |
|---|---|---|---|
| 256JJ | 默认 | 69 节点全部 OK，768,968 拍 | 0.970 |
| 576JJ | `--device-buffer-bytes 131072` | 134 节点全部 OK，5,980,347 拍 | 11.57 |
| 1024JJ | `--max-front-size 300 --device-buffer-bytes 524288` | 214 节点全部 OK，14,010,544 拍 | 0.550 |
| 随机 256 阶（对照） | `--n 256 --density 0.02 --seed 3 --device-buffer-bytes 131072` | 123 节点全部 OK | 1.2e-7（通过） |

本文回答：这是设备实现错误、主元策略问题，还是矩阵本身的问题。

## 2. 方法

`numeric_diagnosis.py` 把一个“PASS/FAIL”拆成三个独立问题：

1. **问题有多难**：原始 A、设备实际分解的矩阵 D_r·A（行置换不改变条件数）、以及两种更强的
   行+列对角缩放下的 2-范数条件数；D_r·A 最小的奇异值（几乎线性相关的方向有几个）。
2. **每个节点分解得好不好**：后向误差 max|F − L·U − S| / max|F|（按元素最大绝对值归一化）。F 用初始镜像加上**设备自己写出的**
   子节点 update 装配，L/U/S 是设备输出；这样可以把节点自身的误差与下层传上来的误差分开。
   同时记录最小静态主元、它在消元前的原始对角元，以及 max|L|（元素增长）。
3. **能不能用来解 Ax=b**：用设备的 FP32 因子在 host 上组装全局 L/U，求解一次，再做 3 步 FP64
   迭代求精；与 FP64 稠密直接求解对照。

FP32 单位舍入误差 u = 2⁻²⁴ ≈ 6.0e-8，粗略地说 FP32 能承受的条件数上限约为 1/u ≈ 1.7e7。

## 3. 结果

本表中的归一化残差为 $\lVert Ax-b\rVert_2/(\lVert A\rVert_F\lVert x\rVert_2+\lVert b\rVert_2)$，
与 solve checker 的无穷范数口径不同；节点和全局分解指标使用元素最大绝对值。

### 3.1 条件数：256、576 真的接近奇异，1024 主要是缩放问题

| 矩阵 | 原始 A | D_r·A（设备分解的矩阵） | 行+列最大值缩放 | Ruiz 行+列缩放 | κ(D_r·A)·u_FP32 |
|---|---|---|---|---|---|
| 256JJ | 5.4e10 | **1.0e10** | 8.3e9 | 7.4e9 | 6.0e2 |
| 576JJ | 2.8e13 | **1.4e13** | 1.0e13 | 7.8e12 | 8.1e5 |
| 1024JJ | 2.2e14 | **1.2e9** | 1.4e9 | 7.3e8 | 7.3e1 |
| 随机 256（对照） | 1.04 | 1.04 | 1.04 | 1.04 | 6.2e-8 |

D_r·A 的奇异值相对最大奇异值：

| 矩阵 | 最小的 6 个 σ/σ_max | < FP32 u 的个数 | < 1e-6 的个数 |
|---|---|---|---|
| 256JJ | 1.0e-10, 5.6e-10, 1.5e-9, 5.6e-9, 7.0e-8, 2.1e-7 | 4 | 12 |
| 576JJ | 7.4e-14, 3.9e-13, 2.6e-11, 8.7e-11, 1.0e-10, 5.8e-10 | 24 | 27 |
| 1024JJ | 8.2e-10, 1.3e-8，随后跳到 2.4e-5 | 2 | 2 |

- 256JJ 和 576JJ 在本次测试收益最好的对角缩放下，条件数仍为 1e10 和 1e13，比 FP32 承受范围高 3～6 个数量级，
  并且分别有 4 个和 24 个奇异值相对最大奇异值低于 FP32 单位舍入误差的方向。**它们是真正接近奇异的矩阵。**
- 1024JJ 原始行最大元跨 0.03～8.4e9 共 11 个数量级。管线现有的二的幂行缩放已把条件数从 2.2e14
  降到 1.2e9，剩下只有 2 个接近零的方向。
- **更强的行+列缩放最多只再降 1.2～1.7 倍**，未把这几个输入带入良态范围；这不是对所有对角缩放的最优性证明。

### 3.2 逐节点：多数节点后向稳定，极小主元节点不是

| 矩阵 | 后向误差中位数 | 后向误差最大值（节点） | 最小主元 / front 最大元 | 该主元消元前的对角元 | max\|L\| |
|---|---|---|---|---|---|
| 256JJ | 3.8e-8 | 2.4e-5（66） | 2.4e-9（根 68：2.5e-6 / 1.06e3） | 0.61 | 2.0e4 |
| 576JJ | 3.1e-8 | 5.0e-3（131） | 1.4e-10（132：2.3e-5） | 0.90 | 3.8e6 |
| 1024JJ | 1.4e-8 | 7.3e-7（206） | 2.6e-7（213） | 0.65 | 8.6e2 |
| 随机 256 | 1.3e-10 | 1.2e-7 | 0.99 | 1.0 | 1.0 |

- **小主元是消元中相消产生的**：对角元原本是 0.6～0.9，经过 Schur 更新后只剩 1e-5～1e-7。用 FP64
  对同一输入做静态消元也会得到同样小的主元，所以这是“矩阵 + 固定消元顺序”的性质，不是 FP32
  造成的。
- 大多数节点的后向误差在 1e-8 量级，支持多数节点分解具有较小后向误差，不能据此证明设备实现不存在任何错误。
- 主元最极端的节点里，|L| 被放大到 1e4～1e6，后向误差随 |L||U| / |F| 增大到 2.4e-5（256）和 5.0e-3（576）。
  这一现象与无主元选择 LU 的误差增长机制一致；单凭这些统计不能排除所有实现缺陷。
- checker 判失败的直接原因是：L = 列元素 / 主元，主元的相对误差约为 u·max|F|/|主元|（例如节点 62：
  6e-8 × 1.23 / 8.6e-6 ≈ 1%），整列 L 随之偏离 FP64 结果。这是**前向误差**，在主元极小时，逐元素
  1e-4 的判据本身就过严。

### 3.3 求解：FP32 因子能否给出可用的 x

| 矩阵 | 全局 max\|Â−LU\| / max\|Â\| | FP32 因子 + host FP64 三角求解一次：归一化残差 / x 相对误差 | 3 步 FP64 修正后：归一化残差 / x 相对误差 | FP64 稠密直接求解的 x 相对误差 |
|---|---|---|---|---|
| 256JJ | 7.7e-5 | 2.2e-7 / 7.6 | 3.3e-7 / 2.3e4（发散） | 1.2e-7 |
| 576JJ | 1.9e-2 | 1.0e-6 / 1.2e2 | 4.1e-6 / 1.2e4（发散） | 7.2e-5 |
| 1024JJ | 2.4e-6 | 1.4e-9 / 4.8e-2 | 2.1e-16 / 3.1e-2（残差收敛） | 8.5e-7 |
| 随机 256 | 1.3e-7 | 1.9e-9 / 3.3e-8 | 7.4e-18 / 1.1e-16 | 4.0e-16 |

- 节点上的局部误差经 update 传到父节点并被放大（256 根节点 front 最大元从约 1 涨到 1e3），全局后向
  误差因此是 7.7e-5、1.9e-2，而不是 1e-7。
- 256JJ、576JJ：FP32 因子求解一次的残差看起来很小，但 x 完全错误（病态问题中“残差小 ≠ 解准”）；
  用 FP32 因子做 FP64 迭代求精**发散**。
- 1024JJ：迭代求精能把残差压到机器精度，x 的误差停在 3e-2，受矩阵病态程度限制。
  （注：本表的迭代求精修正步是用 FP32 因子做 FP64 三角求解。按设备方式改为 FP32 求解后，1024JJ 的
  后向误差停在 1.7e-9，见 [FP32 精度边界实验](../precision_boundary/实验报告.md) §6.7。）
- 对照的随机矩阵：一次求解 x 误差 3e-8，一步迭代求精即达 FP64 精度。

## 4. 结论

以下判断限于原报告列出的输入、缩放、STATIC 顺序与 host 求精方法；原始 JSON 的缺口见文首。

1. **多数节点的后向误差较小，但极小主元节点增长明显。** 良态对照的误差较小，
   真实矩阵少数节点及全局误差较大；因子逐元素偏离 FP64 不能单独归因于实现错误，也不能证明设备无误。
2. **256JJ、576JJ 在所测试的缩放后仍严重病态。** 条件数约 1e10 / 1e13，κ·u_FP32 远大于 1。
   本次 STATIC 因子加 host FP64 三角修正的求精发散；这项观测不是所有主元策略或求精方法均会失败的证明。
3. **静态主元增长是另一层限制。** 相消导致极小主元和较大元素增长，动态主元有望缓解增长；
   设备动态路径尚未接入，未完成同条件对比，也不能靠行交换改变矩阵固有条件数。
4. **所测试的行列缩放收益有限。** 1024JJ 的二的幂行缩放带来较大改善；额外两种行列缩放改善约 1.2～1.7 倍，
   不能外推为所有缩放方案的最优收益。
5. **1024JJ 的 host FP64 修正可将归一化残差降到机器精度，解误差仍约 3e-2。**
   按 FP32 三角修正步执行的另一项实验未达到成功判据；不能将本结果作为设备求精完成证据。

## 5. 对项目的影响

- **FP32 设备有适用范围。** 使用条件应结合条件数、元素增长和误差门限声明，不能声称可准确求解任意非奇异稀疏矩阵。
- **验收判据需要调整。** 逐元素比较 L 与 FP64 适合良态矩阵；对病态矩阵应改为“每节点后向误差 +
  原方程残差 / 后向误差”，并单独报告条件数。
- **需要 host 侧的条件数判断。** 超出 FP32 范围的矩阵应在编译或求解前识别出来，走 FP64 回退或明确
  报告，而不是让设备给出“全部 OK”的结果。
- **设备求精仍需实现并复核。** host FP64 三角修正的收敛结果不能保证设备 FP32 修正也收敛；流程需明确失败诊断、停止条件及高精度回退策略。

## 6. 对此前表述的更正

- 此前写的“FP32 + STATIC 在真实矩阵上 L 因子失真、因子不可用”不准确：多数节点的分解是后向稳定的，
  L 与 FP64 的偏差主要是病态问题下的前向误差；真正的限制是矩阵条件数，以及少数极小主元节点的元素
  增长。
- 此前说“各节点后向误差都在 1e-7 量级”只基于抽查的几个节点；全量统计见 §3.2，最大值分别为
  2.4e-5（256JJ）、5.0e-3（576JJ）。
- 此前建议“补上匹配算法的列缩放”作为优先方向：§3.1 显示其收益最多 1.7 倍，已降为次要方向。

## 7. 复现并保存新批次

先按 [README](../../README.md) 构建 Release 设备。以下从仓库根目录开始，
当前 CLI 默认生成分解及求解命令；与原报告运行配置未必完全一致，结果应作为新批次保存。
设置一个未使用过的批次名，不能写回 `results/2026-10-10/`。

```bash
cd graduation-code/software
EXPERIMENT_RUN="../../experiments/real_matrix_diagnosis/results/local-reproduction"
BUILD="/tmp/gp-rel"
mkdir -p "$EXPERIMENT_RUN/cases/jj256" "$EXPERIMENT_RUN/cases/jj576" "$EXPERIMENT_RUN/cases/jj1024"

../../.venv/bin/python -m src.main --mtx example/256X256JJ.mat \
  --out "$EXPERIMENT_RUN/cases/jj256/art"
../../.venv/bin/python -m src.main --mtx example/576X576JJ.mat \
  --device-buffer-bytes 131072 --out "$EXPERIMENT_RUN/cases/jj576/art"
../../.venv/bin/python -m src.main --mtx example/1024X1024JJ.mat \
  --max-front-size 300 --device-buffer-bytes 524288 --out "$EXPERIMENT_RUN/cases/jj1024/art"

for matrix in jj256 jj576 jj1024; do
  CASE_DIR="$EXPERIMENT_RUN/cases/$matrix"
  "$BUILD/tree_factor_device" --device-dir "$CASE_DIR/art" --out "$CASE_DIR/rep" --backend FP32_SYSTEMC
  "$BUILD/tree_factor_check" "$CASE_DIR/art" "$CASE_DIR/rep"
  "$BUILD/tree_solve_check" "$CASE_DIR/art" "$CASE_DIR/rep"
  ../../.venv/bin/python tools/numeric_diagnosis.py "$CASE_DIR/art" "$CASE_DIR/rep" --json "$CASE_DIR/diagnostic.json"
done
```

病态输入的因子 checker 可能返回失败，保留其退出码和报告；不要为通过而改动门限或删除结果。
只分析条件数时，可省略 `numeric_diagnosis.py` 的设备报告参数，仍需保留编译产物。
保存本批次 `metadata.json`，记录实际 scope、RHS seed、缩放、策略/阈值、容量、命令、
环境、代码/二进制身份及文件 hash；新实验不能冒充 2026-10-10 的旧原始证据。
设备仿真耗时受矩阵、平台和配置影响，大矩阵需数分钟。
